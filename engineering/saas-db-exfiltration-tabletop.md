# 机上演習：未知のアプリ脆弱性で顧客DBの個人データが外部へ送信された朝

火曜09:10、SOC当番に「帳票ワーカーから初めて見る宛先への送信が続いている」とアラートが届く。保守予定はない。何が送られたか、どの処理に不備があるかは、まだ誰にも分からない。最初の判断は、次の送信を止めるためにどの業務を止めるかだ。

## 進行役の準備

Web・モバイル・デスクトップとLLMエージェントは、共通の帳票サービスに処理を依頼できる。Kubernetes上のワーカーがジョブを受け、顧客DBを読み、帳票を配送する。演習用の構成では、このワーカーに固有のDBアクセス権がある。登場する時刻はJST。証拠、契約、顧客、人数はすべて架空とし、操作と対外連絡は演習チケット上で模擬する。

進行役は各場面の引用部分だけを順に読み、参加者の判断を待つ。チェック欄は回答後に使う。各担当は **観測した事実／決めたことと根拠／誰が引き受けたか／次回確認時刻** を残す。少人数の場合は兼任し、承認時に役割を名乗る。[対応プレイブック](../controls/records/governance-operations/product_incident_response_playbook.md)

## 09:10　異常を検知したSOCから当番へ

> SOC「送信は09:04から継続中です。送信元は帳票用Pod。宛先は登録済みの配送先一覧にありません。同じ時間帯にワーカーのDB読み取り量も増えています」。SRE「この機能を止めると、正規の帳票も遅れます」。

- [ ] **SOC → PSIRT・SRE**　時刻、送信元、宛先、送信量の推移、照合した配送先一覧を渡す。内容と人数は未確認と伝え、通信・DB双方の観測がいつから利用できるか調べる。
- [ ] **PSIRT → 全担当**　個人データ漏えいの疑いとして暫定S1で招集する。指揮者と次回集合時刻を宣言し、開発にジョブの特定、法務・CSに契約確認、広報に問い合わせ対応の準備を依頼する。
- [ ] **SRE → 指揮者**　帳票の新規受付・実行中の配送・再試行を止め、対象ワーカーの外向き通信を遮断する。証拠保全は並行して行い、Podやキューを消去する前に稼働版、ジョブID、監査記録、保留中の件数を控える。CSには停止機能と継続可能な業務を伝える。

## 09:25　DBのどの情報が外へ届いたか

> 開発「ジョブJ17の生成記録に、国内の委託元Bの顧客80名分の氏名・メールアドレスと帳票のダイジェストがあります。配送記録では同じダイジェストの帳票について、未承認の外部宛先から受領応答が返っています」。別のジョブはDB読み取りまで追えるが、配送記録の一部が欠けている。

- [ ] **開発・SOC → PSIRT**　J17について、DB上の対象者、出力項目、送信内容、宛先、受領時刻を結ぶ記録を示す。別ジョブについては、送信の有無と対象者の重複を調査事項に残す。指揮者は「Bの少なくとも80名分の漏えいを確認」とS1を確定し、法務に検知時刻と確認時刻を渡す。
- [ ] **SRE → SOC・開発**　ワーカーのDB権限を一時停止し、既存接続の終了を確認する。遮断後の送信試行の拒否、DB読み取りの停止、センサーの稼働を照合する。成功通信が続く場合は送信元を再特定し、隔離範囲を広げるか指揮者と判断する。

## 09:45　委託元へ何を伝えるか

**法務役にだけ渡す資料**　架空の契約台帳によると、自社とBは国内の民間事業者。J17の顧客名簿はBからの受託データで、本人への連絡先はBが管理する。別ジョブには自社が直接取得した利用者情報が含まれる可能性がある。海外拠点・海外向けサービスへの影響は未確認。法務はデータの持ち主、本人との関係、提供地域をCSに照会し、追加の法域や業法を調べる担当と期限を決める。

**進行役から法務へ**「外部宛先から受領応答があります。これだけで、何時に、誰に、どの義務が生じたと言えますか」。法務は09:10の異常検知、09:25に把握した個人データの内容と外部到達、後に判明する悪用の証拠を時系列に置く。個人情報保護法26条・規則7条の各類型を検討し、特に不正目的の行為のおそれを裏付ける事情を記録する。80名という人数だけで判断を終えない。契約上の「疑いを知った時刻」と、各法人が報告対象事態を知った時点をそれぞれ根拠付きで仮置きし、新事実で見直す。[個人情報保護委員会「通則編」3-5-3](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)

> Bの担当者「帳票が届きません。情報漏えいはありましたか。当社からお客様に何と説明すればよいですか」。演習用契約は「受託者が漏えいの疑いを知ってから2時間以内にBの指定窓口へ初報」と定めている。

- [ ] **法務 → 指揮者**　この契約では09:10起算、11:10期限として通知記録を開く。委託元への初報と、当局報告・本人通知について、判断主体、対象、起算事実、期限または次回判断時刻をそれぞれ記録する。[プレイブック5.3](../controls/records/governance-operations/product_incident_response_playbook.md#notification-requirements)
- [ ] **PSIRT・CS → 広報責任者**　初報案を渡す。例「貴社の少なくとも80名分の氏名とメールアドレスを含む帳票が、未承認の外部宛先に届いたことを確認しました。帳票の配送を停止しています。追加の送信と対象者の範囲を調べ、11:00に途中経過をご連絡します。」
- [ ] **広報責任者・CS → B**　法務と文面を確認し、広報責任者が承認する。CSは指定窓口への模擬送信と受領を記録する。不達なら契約上の代替連絡先を照合し、期限前に指揮者へ戻す。

## 10:30　原因は判明したが修正版はまだない

> 開発「自社アプリの帳票処理に、これまで把握していなかった配送先の認可不備がありました。J17の依頼者が指定した配送先には権限がなく、当時の版がその配送を受理したことを確認しました」。事業責任者「午前の締め処理だけでも再開できますか」。

- [ ] **開発・SRE → PSIRT**　Web・モバイル・デスクトップ・エージェントから同じ処理を呼ぶ範囲と、予約・再試行ジョブへの適用範囲を確認する。保留ジョブは宛先と権限の照合が済むまで隔離する。
- [ ] **PSIRT・CS → 事業責任者・B**　帳票停止を継続する条件と、調査で独立性を確認できた業務を説明する。11:00には原因、停止範囲、追加影響の調査状況を続報する。再開時刻の約束は、検証結果がそろってから行う。

## 11:00の続報後　委託元と自社の義務を確定する

> B「初報は受領しました。当局への報告は御社で済んでいますか」。調査班「別ジョブでも外部到達が確認できました。こちらは自社のサポート登録者7名の名簿です。Bの80名との重複は未確認です」。

- [ ] **法務責任者 → Bの個人情報担当**　B受託分と自社取得分で義務の記録を二行に分ける。報告対象なら委託元・委託先双方に原則として報告・本人通知義務がある。Bに報告義務があり、自社が規則9条に従いその時点で把握した事項を速やかにBに通知した場合は、受託分について自社が免除を受ける扱いを記録する。CSの契約初報の写しと宛先・内容・受領を確認し、不足事項を補う。Bの担当者に当局報告と本人通知の引受状況を読み返してもらう。条件が確認できない間は自社の提出担当も置く。[委託先と委託元の義務に関する委員会FAQ](https://www.ppc.go.jp/all_fad_index/fad2-1-2-q2/)
- [ ] **法務 → 模擬報告窓口**　自社取得分は自社が判定する。この演習では、意図的な悪用と外部到達の証拠から規則7条3号に該当すると判断する。所管窓口を特定し、概要、項目、人数、原因、二次被害、本人対応、公表、再発防止策、その他参考事項について判明分で速報を作る。「自社分7名。受託分との重複を照合中」と記し、受付控えをチケットに添付する。速報は知った後速やかに（概ね3〜5日以内が目安）、確報は原則30日以内、同号なら60日以内。担当は自社の認知日から期限を暦に落とす。[委員会の報告手続](https://www.ppc.go.jp/personalinfo/legal/leakAction/)
- [ ] **広報・CS・法務 → 本人通知担当**　Bには本人向け文案と問い合わせ情報を渡し、自社分は自社が状況に応じ速やかに通知する。概要、氏名・メールアドレス、判明した原因、想定される二次被害、身に覚えのない連絡への対処、正規窓口を本人が理解できる言葉で記す。宛先不達を演習に一件入れ、代替連絡手段を確認する。本人通知が困難な場合は、本人の権利利益を守る代替措置が取れるか法務が個別に判断する。

## 翌朝　帳票を再開できるか

> QA「修正版では、テスト用の正規配送は成功し、未承認宛先への配送は拒否されました」。SRE「保留キューに旧版で受け付けたジョブが残っています。処理を戻すと自動で再試行されます」。

- [ ] **開発・QA → S1担当役員**　修正版の識別子、通常・予約・再試行の検証結果を示す。SREは旧ジョブを隔離したまま段階的に配信する計画、監視担当、再遮断条件を提示する。担当役員は配信可否と条件を記録する。
- [ ] **SRE・SOC → PSIRT**　承認後、稼働版の照合、旧ジョブの隔離、テスト用帳票の配送先、拒否イベントと監視の稼働を確認する。進行役は条件がそろえば「新規の正規帳票は配送成功、旧ジョブは保留」と返す。指揮者は新規分の再開をCSへ伝え、保留分の個別確認に担当を置く。
- [ ] **指揮者 → 後任**　漏えい済み帳票の扱い、記録欠測期間の追加調査、委託元・当局・本人への対応状況を引き継ぐ。各項目に担当、次回更新時刻、完了を判断する人を付ける。

## 振り返り

**確報前の最終カード**　監査記録の保管期限を過ぎた期間があり、追加人数を確定できない。法務役は速報との差分、調査した期間と手段、未判明の理由、再発防止策と担当を示し、期限内の模擬確報を提出する。後日判明事項を追完する担当も残す。進行役はBへの通知、自社の当局提出、本人通知について、各控えの宛先・時刻・対象範囲が一致するか照合する。

記録係は、①遮断の効果を示した証拠、②少なくとも80名と説明した根拠、③Bへの初報・続報の受領記録、④保留ジョブの扱いを含む配信承認を読み返す。参加者は、自組織の記録と権限で同じ判断ができるかを答える。不足があれば、一つ選んで改善担当・期限・次回演習での確認方法を決める。
