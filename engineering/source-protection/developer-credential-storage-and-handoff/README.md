# ENG-SOURCE-007: Developer credential storage and handoff

対応するcontrol：[PSB-SOURCE-007](../../../controls/records/source-protection/psb-source-007-developer-local-credential-storage/README.md)

開発者が本物のトークンを`.env`へ置かずに作業できるよう、**保管場所**と**利用時に渡す経路**を別々に決めます。対象はGit、クラウド、package registry、社内APIなどの開発用認証情報です。

## まず決めること

| 場面 | 判断すること |
|---|---|
| 保管 | OSの資格情報保管機能、承認済みの秘密情報管理サービス、対話的なログインなどから、対象の認証情報に合う方式を選ぶ。作業リポジトリの`.env`、シェル設定、スクリプトを実際の値の保管場所にしない |
| 長く残る値を減らす | サービスが対応する場合、固定トークンより対話的なログイン、短命なセッション、持ち出せない鍵を選ぶ。対応しない場合は、長期の値の用途・所有者・見直す時点を決める |
| 利用 | どのCLI・IDE・処理が、どの値を、いつ必要とするかを決める。ツール固有の認証連携が使えるなら、その受け渡し範囲を確認する |
| 一時的な受け渡し | 環境変数、標準入力、一時ファイルなどが必要な場合は、子プロセス・同一利用者の別処理・ログ・終了後の残存を確認する。環境変数を安全な保管庫と呼ばない |
| 遠隔・隔離環境 | 作業領域やホームディレクトリを丸ごと共有せず、必要な値と利用時間だけを選ぶ。遠隔環境の破棄と認証情報の失効を混同しない |

一例として、リポジトリには値のない`.env.example`だけを置きます。実際の値は承認した保管先へ置き、利用時に対象のCLIだけが受け取る経路を選びます。CLIが環境変数しか受け取らない場合も、端末全体で長く設定するのではなく、その呼出しに必要な範囲へ限定します。具体的なOSや製品の手順は、採用先が決まってから確認します。

組織の端末設定や開発環境の案内で、この取得方法を使えるようにします。「平文へ保存しないでください」と知らせるだけでは、代わりの作業経路がありません。

## 失敗しやすい経路

- `.gitignore`へ`.env`を追加しても、同じ端末の別処理やバックアップからの読み取りは止まりません。
- キーチェーンに保存しても、取り出した値をシェル設定へ書けば保管先を変えた意味がありません。
- OSの資格情報保管機能という名前だけで、同じ利用者の別アプリからの読み出しが拒否されるとは判断しません。採用する方式のアクセス設定を確認します。
- 環境変数は受け渡しに使えますが、継承した子プロセスや診断出力へ広がる場合があります。
- テスト用に発行した実際の短命な値も、期限が切れるまでは認証情報です。無効なダミー値と区別します。
- 既に値が漏れた疑いがあれば、ローカルファイルの削除だけで終えず、[Credential exposure containment](../../governance-operations/credential-exposure-containment/README.md)へ渡します。

## 確認と限界

レビューでは、少なくとも一つの開発作業について、保管場所、値を受け取る処理、利用後に残る場所を図にします。[診断項目](../../../controls/records/source-protection/psb-source-007-developer-local-credential-storage/README.md#診断で確認する項目異常時テスト)を使い、作業領域・ログ・バックアップなどの観測できない範囲は未確認とします。実際の値はレビュー資料へ記録しません。

このpatternは方式を選ぶためのガイダンスです。特定OSや秘密情報管理製品での導入・拒否は確認していません。技術別の実装例は、採用先と安全な使い捨て対象が決まり、導入と確認に役立つ場合だけ追加します。根拠と採否は[参照資料記録](../../../sources/README.md#ref-developer-local-credentials-001)にあります。
