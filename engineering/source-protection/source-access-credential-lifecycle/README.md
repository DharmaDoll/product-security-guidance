# ENG-SOURCE-001: Source credential lifecycle

対応するコントロール：[PSB-SOURCE-004](../../../controls/records/source-protection/psb-source-004-source-access-credential-lifecycle/README.md)

## 概要

利用者、自動処理、開発ツールへソース管理基盤の権限を与えるとき、認証情報の種類だけでなく、
発行、受け渡し、利用、棚卸し、失効、監査までを一つのライフサイクルとして設計します。

## 利用場面

- 開発者がGitクライアント、CLI、IDEからソースコードを読み書きする。
- CI、ボット、リリースサービスがリポジトリへアクセスする。
- MCPサーバーや開発ツールが利用者に代わってリポジトリの情報を読む。
- 退職、異動、端末紛失、インシデントの発生後に権限を止める。

## 適用範囲と前提

対象は、ソース管理基盤へ提示される利用者またはワークロードの認証情報と、そこから派生するセッションです。
端末全体の防御、ソース変更内容のレビュー、AIエージェントのツール認可、ソース管理基盤自体の侵害は隣接する問題です。

ソース管理基盤とIdPが、対象リソース、許可する操作、有効期間、失効を強制できることを前提とします。

## 資産と信頼境界

主な資産は、ソースコード、ワークフロー、リリース設定、リポジトリのメタデータと、それらを操作する権限です。

```text
利用者／ワークロード
       |
       v
承認された認証と認証情報の発行
       |
       v
保護された保管場所 -> 必要な利用プロセス
       |
       v
ソース管理基盤での認可 -> リポジトリ操作
       |
       v
現在の棚卸し／監査／失効
```

次の境界を別々に確認します。

1. 本人または主体の確認から、認証情報の発行まで。
2. 保護された保管場所から、利用プロセスへの受け渡しまで。
3. 認証情報の提示から、ソース管理基盤上のリソースと操作の認可まで。
4. ライフサイクル上の事象から、認証情報とセッションの失効まで。

## 脅威と悪用経路

| 脅威 | 悪用経路 | 影響 |
|---|---|---|
| 認証情報の窃取 | 平文ファイル、親プロセスの環境、悪意ある拡張機能から取得 | ソースコードの読取・変更、ワークフローの悪用 |
| 過剰権限 | 一つの自動処理用認証情報で、すべてのリポジトリへ書き込める | 被害範囲の拡大 |
| 主体の混同 | 自動処理が開発者のアカウントを共有 | 所有者、目的、失効条件が曖昧になる |
| ライフサイクルのずれ | 退職や用途終了後も権限やセッションが残る | 攻撃者が長期間居座れる |
| 監査情報の不足 | 現在の権限と過去の事象を結び付けられない | 検知と封じ込めの遅延 |

## 前後の段階との受け渡し

この設計パターンは、[横断分析の軸](../../../docs/ANALYSIS_LENSES.md)では、開発端末と端末内の信頼境界、
ソース管理基盤、AI支援開発、CI/CDのIDという複数段階に接します。

| 境界 | 受け取るもの | このパターンで決めること | 次へ渡すもの |
|---|---|---|---|
| 開発端末／AIツール | 利用者またはツールの認証要求 | 認証情報の保管、受け渡し、権限、期間 | 限定されたソース管理上の権限 |
| ソース管理基盤 | 主体、対象リポジトリ、操作 | サービス提供側での認可と失効 | 誰が何を行ったかを追跡できる監査情報 |
| CI/CDの自動処理 | 自動処理の目的と必要な操作 | 利用者の認証情報とワークロードIDの分離 | 短命で処理内容を限定したID |
| インシデント対応 | 退職、紛失、漏えい、用途終了 | 認証情報と派生セッションの失効 | 影響調査に使う主体、対象、利用履歴 |

モデルやAIエージェントが「許可してよい」と出力しても、それを認可判断にはしません。
これは[`REF-PORTFOLIO-001`](../../../sources/README.md#ref-portfolio-001)から採用した境界であり、ツールと引数に対する
実行時認可はこのパターンの外側で別に強制します。

## セキュリティ不変条件

- 利用者と自動処理の権限を、同じ長期認証情報に集約しない。
- 認証情報を、主体、目的、対象リソース、許可する操作、有効期限と結び付ける。
- 保護された保管場所から、必要な利用プロセスだけへ受け渡す。
- ライフサイクル上の事象が発生したら、認証情報と関連セッションを無効化し、それらによるアクセスを拒否する。
- 認証情報の値を記録せずに、現在の権限と重要な事象を調査できる。

## アーキテクチャ上の判断

### 利用者かワークロードか

対話的なアクセスには、組織が承認した利用者認証を使います。自動処理には利用者のトークンを再利用せず、
対象リソースと処理内容を限定できるアプリケーションIDまたはワークロードIDを使います。

### 適用範囲をどこで狭めるか

認証情報の発行時だけでなく、ソース管理基盤側のリポジトリ選択と操作権限で強制します。
ツール側の許可一覧は多層防御の一部であり、サービス提供側の認可の代わりにはなりません。

### 保管と受け渡しを分ける

キーチェーンやシークレット管理サービスは保管場所です。環境変数やプロセス入力は受け渡し経路です。
安全な保管場所から取り出した値でも、親プロセス全体へ渡せば、周辺の処理が利用できる権限になります。

### 有効期限と失効を分ける

有効期限は、権限が存続する最長時間を制限します。失効は、インシデントやライフサイクル上の事象を受け、
期限前でも権限を止めます。両方を設計します。

## 実装方式の選択

| 状況 | 推奨する方向 |
|---|---|
| 開発者による対話的なGit操作 | SSO／MFAへ結び付いた承認済みOAuth、またはハードウェア保護されたSSH鍵など |
| リポジトリの自動処理 | インストール先、リポジトリ、権限を限定した短命なアプリケーションID |
| 開発ツール／MCP | OAuthを優先し、代替の認証情報はツール専用、リソース限定、短命にする |
| 緊急操作 | 通常権限を恒久的に広げず、別承認と期限を持つ緊急経路 |

製品名だけで安全性を決めず、実際に付与される権限と受け渡し経路を比較します。

## 確認事項

設計レビューでは、少なくとも次の状態を観測します。

- 最新の棚卸し結果が、利用者、自動処理、アプリケーション、鍵、権限、セッションの対象範囲を表している。
- 許可した操作は成功し、付与していない操作と対象外のリソースは拒否される。
- ライフサイクル上の事象が発生した後に、古い認証情報と派生セッションが拒否される。
- 監査ログ上の事象を、伏せ字にした認証情報の識別子、主体、リソース、操作と結び付けられる。
- サービス提供側、IdP、端末の未確認領域を、サンプルの成功で補っていない。

具体的なテスト環境は、プラットフォーム別の実装例または評価が受け持ちます。

## 運用と対応

所有者不在、用途終了、長期未使用、異動、退職、端末紛失、漏えいを、レビューと失効の契機にします。
インシデント時は、代替の認証情報を発行する前に古い権限を封じ込め、ソースコード、ワークフロー、
リリースへの利用履歴を調べます。

## 残余リスク

ソース管理基盤やIdPの制御面の侵害、認証済み端末セッションの乗っ取り、既に複製されたソースコードは残ります。
