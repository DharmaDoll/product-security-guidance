# サプライチェーン攻撃の対策

依存の更新や外部CIツールから不正なコードが入り、開発端末・ビルド・公開の権限で動く経路を、取得から復旧までつないで考えます。開発者・開発基盤担当者・プロダクトセキュリティ担当者が、全体像、具体的な対策、工程別の設計を目的に合わせて選ぶ入口です。

## 全体像と実践

| やりたいこと | 最初に読む文書 |
|---|---|
| 対策の役割と、組み合わせても残る経路を理解する | [多層防御の全体像](supply-chain-defense.md)：採用・実行前、実行時、判明後の三つの場面で考える |
| 自分の環境に対策を入れる・設定を見直す | [実践ガイド24章](supply-chain-countermeasures.md)：設定の違い、適用条件、確かめ方を対策ごとに読む |

初めて読む場合は全体像から24章へ進みます。対策が決まっている場合は、24章の目次から直接選べます。担当や工程の分け方まで設計する場合は、以下の詳細へ進んでください。

## 工程別の詳細

| 確かめたいこと | 読む文書 |
|---|---|
| 依存の変更を審査し、承認した入力をビルドへ渡す | [依存の選定・更新・取得](dependency-update-to-build.md) |
| 外部PRの検証と、正規ビルド・公開の権限を分ける | [PR検証から公開への引き渡し](pull-request-to-release-build.md) |
| CIの共有状態を通じて、未信頼の処理が後続へ影響しないようにする | [cacheとrunnerの扱い](ci-state-and-runner-lifecycle.md) |
| 承認したビルドの出力を、署名・公開し、検証した対象を使う | [ビルド・署名・公開・使用](release-build-to-use.md) |
| 部品と成果物・稼働先を結び、問題のある依存の利用先を調べる | [SBOMと影響調査](sbom-to-vulnerability-response.md) |
| 信頼できる入力から再構築し、旧成果物の非稼働まで確認する | [成果物の再構築・置換](deployed-artifact-recovery.md) |

侵害が疑われる場合は、調査の完了を待たずに動けるよう、共通の[初動・対応・再開](../security-signal-to-response.md)と、上の影響調査・復旧の文書を合わせて読みます。
