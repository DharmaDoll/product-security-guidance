# Agent extension admission

`ENG-AI-001` / `ai-development-security`

## 解く設計問題

担当者が審査した拡張の内容と権限を、実際に読み込む拡張へ結び付けます。読者は開発環境の管理者、product security担当者、拡張を採用する開発者です。

開発者端末・IDE・CLI・repository・CIで使う拡張を対象にします。製品自体のAI機能への適用設計は[ai-security-foundry](https://github.com/DharmaDoll/ai-security-foundry)へ委ねます。[対象範囲](../../../docs/SECURITY_SCOPE.md)に沿って方式を選びます。

```text
取得元・内容を固定
  → 内容と要求権限の独立審査
  → 同じ内容を使った評価
  → 期限付きの承認記録
  → 読み込み時に内容・権限・失効状態を照合
  → 実行環境による操作ごとの認可
```

## 実装方式を選ぶ

| 方式 | 確認する対応 | 運用上の代償 |
|---|---|---|
| Local Skill・prompt | 審査した文章・参照ファイルと、実際に読み込む内容 | 自動更新や追加ファイルで審査範囲が変わる。指示文だけではtool権限を制限できない |
| Local MCP・plugin | Source、配布物、依存関係、設定と、起動するprocess | 実行環境の隔離と更新管理が必要。起動scriptや子processも対象になる |
| Remote MCP | 承認した提供者・接続先・toolと、稼働版の証拠 | 運用を提供者へ委ねる一方、source commitだけでは稼働内容を確認できない |

これらは設計上の選択肢であり、特定clientの対応表ではありません。利用する製品が読み込み内容や実効権限を確認できるか、採用前に調べます。

## 審査と権限制限の担当

申請者は目的、必要なファイル・通信先・toolを説明し、独立したreviewerが指示、コード、tool schema、インストール・更新処理を確認します。
評価担当は同じcommit・digestについて、通常作業の成功と禁止操作の試行を調べます。管理者は承認記録を書き換えられる主体と、実行環境の制限を変更できる主体を管理します。

権限の申告は、実行環境の設定へ対応付けます。審査された権限を超える通信や書込みは、modelの出力を信頼することなく実行環境で拒否する必要があります。
GitHub MCPの認証情報は[Source credential lifecycle](../../source-protection/source-access-credential-lifecycle/README.md)へ引き渡し、toolの承認と認証情報の発行を同じ判断にしません。

## 更新・失効・復旧

内容、提供者、tool schema、要求権限、評価条件が変わったら再審査します。承認情報と必要なartifactを保持し、上流の削除後も何を審査したか追跡できるようにします。
失効情報の収集先、対象範囲、許容する鮮度を決め、更新不能なら利用を止める経路を設けます。外部feedがない場合は、組織の承認・失効台帳を誰が更新するか明示し、情報がないことから有効と推定しません。
既存session、token、子processを止める作業と、次回読み込みを拒否する作業は別々に確認します。

### 失効を実行環境へ渡す

失効の対象は表示名ではなく、拡張ID・種類・内容の識別情報・承認記録の版で特定します。実行側へは、失効の効力が生じる時刻、対象となる権限、判断の正本とその鮮度も渡します。配布・同期の経路を認証し、古い有効状態で新しい失効を上書きさせません。
以下は本PJの責任分界の設計であり、特定製品の停止機能を確認した結果ではありません。

| 場面 | 判断と担当 | 完了とみなすための確認 |
|---|---|---|
| 承認の取消 | AI-002の所有者が対象と理由を確定する | 正本に記録されたこと。これだけで実行停止完了とはしない |
| 新規読み込み・未送信の呼出し | AI-004の実行側が現在の承認へ照合する | 失効対象の利用と、旧承認を使う待機中の呼出しが拒否される |
| 既存session・子process | 開発環境の管理者が停止・隔離を行う | 対象を特定して停止を確認する。次回起動の拒否と分ける |
| Tokenと派生権限 | 認証情報の所有者がSOURCE-004の手順で失効する | 接続先で古い権限が使えなくなる。拡張を削除しただけで済ませない |
| 送信済みの外部操作 | 操作の所有者が要求IDで結果を照合する | 成功・未実行・結果不明を区別する。取消をrollback成功としない |
| 未接続の端末・収集不能 | 管理者が未到達の範囲を保持する | 未確認を全端末適用済みとしない。再接続時にも古い許可で再開させない |

実行側は承認の確認から送信までの間に状態が変わる可能性も扱います。送信直前の再確認、版に結び付いた短命の許可など、採用する方式と残る時間差を定めます。同期周期だけから即時失効を保証しません。
通知と定期照合を組み合わせても、失効の即時反映ができない製品・端末はあります。許容する遅延、未接続時の利用停止条件、代替の隔離手段を管理者が決め、達成できない場合は採用範囲を狭めます。

停止・復旧の全体は未移行の別境界です。AI-002の台帳とAI-004の利用拒否だけで、全端末の封じ込めや復旧を完了したとは扱いません。参照根拠と今回の解釈は[資料記録](../../../sources/README.md#ref-development-runtime-reconciliation-001)に残します。

## 採用時に確認すること

### 承認記録と実行時の一覧を照合する

インストールを禁止する設定だけでは、以前から動いている拡張が停止したとは分かりません。管理対象の端末・client・観測時刻・収集範囲を明示し、実際に有効な拡張の種類、起動元または接続先、内容、利用可能なtoolを承認記録と照合します。
一覧が空でも、未導入なのか収集失敗なのかを区別します。未対応の拡張種別や一部端末の欠落は、正常な一致に含めません。許容する鮮度は更新速度と失効要件から定め、旧サンプルの1時間を一律の基準にしません。

Tool一覧の変更は再照合の契機です。通知だけに依存せず、一覧の再取得や定期照合を組み合わせ、確認できない追加toolは実行させません。Remote MCPの一覧取得だけでは、提供者が実際にその実装を動かすことまで証明できません。
MCP仕様のannotationsは振舞いの説明です。未信頼serverの「読取り専用」という申告を、そのまま書込み権限や自動実行の許可へ変換しません。仕様と採否は[実行時照合の資料記録](../../../sources/README.md#ref-development-runtime-reconciliation-001)を参照してください。

起動・利用時の制限は[隔離](../development-runtime-isolation/README.md)、各呼出しの対象と引数は[操作認可](../development-action-authorization/README.md)で強制します。審査側と実行側が同じ拡張ID・内容・方針の版を使っていることが受け渡しの条件です。

### 確認シナリオ

同名で内容が異なる拡張、自己承認、権限の追加、期限切れ、失効、失効情報の欠落、異なるdigestの評価結果、未対応の拡張種別を与え、読み込み前に止まることを確認します。
評価では審査記録の`approved`だけを確認せず、代表的な作業と禁止操作を実際に試します。機微情報は合成データに置き換え、prompt全文やtokenを通常の保存証拠へ含めません。

旧実装の5件の合成artifactとverifierは、記録間の対応を検査するものとして保留します。内容審査の正しさ、実サービスの挙動、稼働版の証明、失効後の停止は検証していません。
旧profileではplugin・外部promptを`deny-not-installed`としており、この移行で有効化したとは扱いません。
