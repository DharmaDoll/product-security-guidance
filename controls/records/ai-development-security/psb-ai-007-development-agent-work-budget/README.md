# PSB-AI-007 — Development agent work budget

## 問い

開発agentの各操作が許可されていても、一つの作業が時間・費用・呼び出し回数を使い続ける前に止められるか。

例えばCI上のagentがテスト失敗の修正を繰り返すと、個々のテストやmodel呼び出しに問題がなくても、作業全体の費用や外部サービスへの負荷は増え続けます。「必要なら続ける」という指示は、実行側の上限の代わりになりません。

## できてはいけないこと

Agentの判断、再試行、sessionの再開、子作業への分割で上限を越える。利用量が取得できない状態をゼロとして続ける。停止を記録した後も新しい呼び出しが実行される。

## 適用範囲

IDE・CLI・repository連携・CIで使う開発agentの一作業と、それに属するmodel・tool呼び出し、再試行、子作業を対象にします。守るのは開発用の利用予算、外部サービス、開発環境と作業に渡した権限です。外部資料の投稿者による長い処理の誘導、agentの誤動作、無制限の再試行、計測・停止処理の障害を扱います。

製品のAI機能や顧客向け推論サービスは[別PJ](../../../../docs/SECURITY_SCOPE.md)の対象です。組織全体の支出上限、runnerのCPU・memory制限、個別操作の認可は隣接する別の境界です。

## 必要なセキュリティ特性

| ID | 満たすべき状態 |
|---|---|
| DEV-BUDGET-1 | 作業の識別子、責任者、対象範囲、必要な上限をagentの外側で決める。同じ作業の再開・再試行・子作業で残り予算を作り直さない |
| DEV-BUDGET-2 | 必要な利用量について、計測元・単位・鮮度と、使用済み・実行中の割当を区別する。不足や不明をゼロにしない |
| DEV-BUDGET-3 | 新しいmodel・tool呼び出しの前に、必要な残り予算を実行側で確保する。並列処理も同じ残り予算を使い、agentが方針を変更して上限を増やせない。経過時間は独立した実行期限へ結ぶ |
| DEV-BUDGET-4 | 上限到達、必要な計測の障害、停止判断の不成立で新しい処理を許可しない。ローカルの実行停止と送信済み操作の結果を分け、結果不明を未実行や自動再試行へ変えない |
| DEV-BUDGET-5 | 拒否の反復、承認の再利用、停止経路の障害を通常の利用量だけに埋めず、独立した実行方針と調査担当へ渡す。残り予算を根拠に未承認操作を許可しない |
| DEV-BUDGET-6 | 作業・方針・利用量・割当・停止理由・結果状態を秘密情報を増やさず追跡する。通知不達、未実施、取得失敗、停止未確認を成功と区別する |

## 実装判断の羅針盤

[設計パターン](../../../../engineering/ai-development-security/development-work-budget-gate/README.md)で、実行時間だけを制限する方法と、各呼び出し前に共通の予算を確認する方法を比較します。全ての量を同じ仕組みで測る必要はありません。費用の厳密な上限を主張するなら、遅れて届く請求情報の監視だけでは足りず、次の呼び出しが消費し得る量も制限できる必要があります。

まず時間と呼び出し回数から始める構成でも、どの量が制限されないかを明示します。[Linux timeoutの実装例](../../../../engineering/ai-development-security/development-work-budget-gate/implementations/linux-timeout/README.md)は、非対話のローカル実行時間だけを具体化します。これだけで全特性を満たすとは扱いません。

## 診断で確認する項目（異常時テスト）

以下は確認項目であり、実agentでの診断結果ではありません。

- 同じ作業を再開、再試行、子作業へ分割しても、残り予算を初期値へ戻せないか。
- 残り予算を複数の呼び出しが同時に参照しても、合計で上限を越える割当が発生しないか。
- 応答の長さ、tool内部の再試行、間接的なAPI呼び出しを使って、計測していない経路へ消費を移せないか。
- 利用量の欠落、古い計測、単位・通貨・価格の不明で、必要な判定を通過していないか。
- Agentが上限設定を編集する、別の認証情報で直接APIへ接続する、停止処理を外す経路を使えないか。
- 上限後の「読取り」や「要約」も無制限にmodel・外部APIを使っていないか。
- 実行期限で親だけが止まり、子processや別jobが続いていないか。未確認の停止を完了扱いしていないか。
- タイムアウト後、送信済みの公開・変更を未実行と誤認して再送していないか。
- 利用量が上限以内でも、承認の再利用や停止判断の障害を許可へ変換していないか。

## 保証しないことと前後の責任

[AI-004](../psb-ai-004-development-agent-runtime-boundary/README.md)は何を実行してよいかを判断し、本controlは許可された処理の累積量を制限します。予算があることは操作許可ではありません。[AI-003](../psb-ai-003-development-content-injection-boundary/README.md)は作業を長引かせる外部資料の指示権限を扱います。

[CI runner](../../cicd-security/psb-cicd-007-runner-lifecycle-isolation/README.md)の破棄や[workloadの資源上限](../../container-cloud-iac-security/psb-container-007-workload-resource-consumption-bounds/README.md)は、外部model APIの支出や一作業の再試行回数を自動的には制限しません。停止しても、漏えいした認証情報の失効や既に起きた外部変更の復旧は別途必要です。生成した変更の正しさ、モデルの安全性、組織全体のサービス可用性も保証しません。
