# テスト修正が終わらないとき

CIで動く開発agentへ「失敗したテストを修正し、PRを準備する」と依頼します。Agentはログを読み、修正し、テストし、modelへ結果を返します。外部のIssueには「失敗したら別の方法を何度でも試す」と書かれています。Agentがその指示を採用しなくても、解決策を見つけられず同じ作業を繰り返す場合があります。

ここで、ファイルの読取りとテスト実行は許可済みです。Modelの応答ごとの長さも制限されています。それでも繰り返すたびにAPI利用料、テスト用の時間、外部サービスへのアクセスは増えます。許可された一操作と、依頼全体で許される消費量は違います。[AI-004](../psb-ai-004-development-agent-runtime-boundary/README.md)は前者、[AI-007](README.md)は後者を扱います。

この依頼を識別する作業IDと上限を、agentを起動する側で決めます。再試行は同じ作業の続きです。Sessionを再開したり子agentへ渡したりしても、利用済みの量が消えるわけではありません。並列の子作業を起動する場合は、両者が同じ残り予算を使う前に、それぞれに使える分を確保します。この確保を**予約（reservation）**と呼びます。単に両者が同じ残高を読むだけでは、同時に開始して合計で超える可能性があります。

どの上限を使うかは作業によります。時間の上限は長時間の実行を止め、呼び出し回数は反復を制限します。費用の上限には、model、入力、最大出力、価格、並列の実行中要求など、次の利用額を見積もる情報が必要です。後から届く請求情報だけで厳密な停止を約束できるとは限りません。正確に制限できない量は、その限界を採用判断へ戻します。

## 止めたあとに残ること

ローカルの実行期限が来ると、agentのprocessを終了できます。しかし、その直前に外部サービスへPR作成を送信し、応答だけ失った場合はどうでしょうか。Processを止めても、PRが作られなかったとは分かりません。結果不明として要求と実行先を照合し、同じ変更を自動で再送しない責任を[操作認可pattern](../../../../engineering/ai-development-security/development-action-authorization/README.md)へ渡します。

停止後の要約もmodelや外部APIを使えば費用が発生します。「読取りだけなら続けてよい」は消費量の制限になりません。終了処理を許可するなら、その分も先に確保するか、modelを使わない方法で状態を残します。

## 振り返る問い

- 応答一回の最大token数を設定しただけで、依頼全体の費用も制限できると考えていないか。
- タイムアウトした作業を新sessionで再開するとき、誰が残り予算や追加枠を判断するか。
- Agentが上限を編集できる場所や、計測されないAPI経路はないか。
- 「止めた」というログから、どのprocessが止まり、どの外部操作が結果不明かを辿れるか。

[Linuxの実装例](../../../../engineering/ai-development-security/development-work-budget-gate/implementations/linux-timeout/README.md)でローカルの停止を試し、[設計パターン](../../../../engineering/ai-development-security/development-work-budget-gate/README.md)でAPI・tool側の上限へ戻って考えます。
