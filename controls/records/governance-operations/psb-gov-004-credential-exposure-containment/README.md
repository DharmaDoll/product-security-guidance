# PSB-GOV-004: Credential exposure containment

**認証情報が漏れた疑いがあるとき、古い権限を止め、その間に何が行われたかを調べられるか。**

たとえば、パッケージ公開用のトークンをリポジトリへ誤って送ったとします。新しいトークンで公開処理が動いても、古いトークンが使えるなら対応は終わっていません。漏れてから止めるまでに、不正な公開がなかったかも確認が必要です。

## 満たすべきこと

1. **対象をつかみ、止める。** どの認証情報か、誰が管理し、何ができ、どの処理が使っているかを調べる。被害が進み得るときは全容の判明を待たずに古い権限を止め、残る不明点を記録する。調査に必要な記録も、可能な範囲で残す。
2. **使う処理を移す。** 必要な処理は権限を広げずに新しい認証情報へ移すか、停止する。トークン本体だけでなく、既存セッションや発行条件など、使える状態が残っていないか確認する。
3. **古い権限の拒否を確かめる。** 新しい認証情報で動くことと、古い権限が使えないことは別に確認する。確認できなければ「対応済み」にしない。実際の値をチケットやテストへ広めない。
4. **影響を調べる。** 漏れていた可能性がある期間の操作を調べ、変更されたソースや公開された成果物などの対象を影響調査へ渡す。ログが取れない範囲や未確認の処理を残したまま、調査完了とはしない。

<a id="failure-checks"></a>

## 診断で確認する項目（異常時テスト）

- 新しいトークンで処理が動いただけで、古いトークンや既存セッションも使えなくなったと判断していないか。
- 主な処理だけを更新し、緊急用の処理や別の利用先に古い権限が残っていないか。新しい権限を以前より広げていないか。
- ログが0件でも、必要な期間や操作を調べられなかった場合に「悪用なし」としていないか。
- 失効や調査が未確認なのに対応を閉じたり、認証情報の値を記録や通知にコピーしたりしていないか。

これらは机上演習や診断で使う確認項目であり、実際の認証情報を失効・検査した記録ではありません。

## このコントロールの範囲

対象は、開発・CI・公開・デプロイなどに使う認証情報の漏えいが疑われた後の封じ込めと影響調査への引き渡しです。普段の権限管理は[SOURCE-004](../../source-protection/psb-source-004-source-access-credential-lifecycle/README.md)、共有前の検査は[SOURCE-002](../../source-protection/psb-source-002-secret-publication-boundary/README.md)、公開情報からの発見は[SOURCE-003](../../source-protection/psb-source-003-public-source-exposure-triage/README.md)で扱います。成果物や稼働環境への最終的な対応は[GOV-001](../psb-gov-001-supply-chain-impact-assessment/README.md)などで判断します。このコントロールだけで、インシデント全体の復旧や悪用が一度もなかったことは証明できません。

認証情報の種類ごとに何を止め、どう安全に確かめるかは[engineering](../../../../engineering/governance-operations/credential-exposure-containment/README.md)を参照してください。7つの特性と根拠のIDは[control.yaml](control.yaml)、資料の採否は[Sources](../../../../sources/README.md#ref-credential-exposure-containment-001)、フレームワークとの関係は[マッピング](../../../../mappings/frameworks.yaml)、旧成果物との対応は[移行記録](../../../../docs/MIGRATION_GOVERNANCE_OPERATIONS.md#credential-exposure-migration)にあります。
