# PSB-GOV-004: Credential exposure containment

**認証情報が漏れた疑いがあるとき、古い権限を止め、その間に何が行われたかを調べられるか。**

## なぜ必要か

たとえば、パッケージ公開用のトークンをリポジトリへ誤って送ったとします。新しいトークンで公開処理が動いても、古いトークンが使えるなら対応は終わっていません。漏れてから止めるまでに、不正な公開がなかったかも確認が必要です。

## 満たすべきこと

1. **対象をつかみ、止める。** どの認証情報か、誰が管理し、何ができ、どの処理が使っているかを調べる。被害が進み得るときは全容の判明を待たずに古い権限を止め、残る不明点を記録する。調査に必要な記録も、可能な範囲で残す。
2. **使う処理を移す。** 必要な処理は権限を広げずに新しい認証情報へ移すか、停止する。トークン本体だけでなく、既存セッションや発行条件など、使える状態が残っていないか確認する。
3. **古い権限の拒否を確かめる。** 新しい認証情報で動くことと、古い権限が使えないことは別に確認する。確認できなければ「対応済み」にしない。実際の値をチケットやテストへ広めない。
4. **影響を調べる。** 漏れていた可能性がある期間の操作を調べ、変更されたソースや公開された成果物などの対象を影響調査へ渡す。ログが取れない範囲や未確認の処理を残したまま、調査完了とはしない。

## 設計時に決めること

| 判断 | 確認すること |
|---|---|
| 何を止めるか | 認証情報の値を記録せず、提供元の識別子、所有者、権限、利用先、関連セッション、発行条件を調べる。種類によって失効単位と反映時間が違う |
| どう移すか | 判明した利用先を一つずつ移行、停止、隔離、または期限付きの非該当に分ける。新しい権限を古いものより広げない。緊急用の処理も見落とさない |
| どう拒否を確かめるか | 新しい値で動くかとは別に、古い権限と関連するセッションが使えないことを確認する。提供元の状態やセッション一覧を使う。無害な操作で確認する場合も、実環境への影響と値を広める危険を先に評価する |
| 何が行われたか | 漏れた可能性がある期間のログを、時刻、取得権限、保存期間、取得漏れまで確認する。変更されたソースや公開された成果物を識別して[GOV-001](../psb-gov-001-supply-chain-impact-assessment/README.md)へ渡す |

## 認証情報の種類で変わる確認点

| 種類 | 値の交換以外に確認すること |
|---|---|
| APIトークン | 関連する認可とセッション、すべての利用先、利用履歴 |
| SSH鍵・証明書 | 登録鍵、証明書の失効、既存セッション、接続先 |
| 署名鍵 | 署名操作の停止、旧鍵への信頼、漏れていた期間に署名された成果物 |
| 短命なワークロード認証情報 | 新規発行の停止、発行条件や信頼設定、発行済みセッション |
| クラウドの鍵・連携セッション | 鍵とロールの信頼設定、残るセッション、操作対象と利用履歴 |

提供元によって実際に止められる単位は異なります。短命な値が自然に失効しても、発行条件が悪用できるままなら対応は終わりません。

## 記録と不可逆な操作を分ける

対応記録には、対象の識別子、担当者、漏れた可能性がある期間、止めた操作と結果、利用先ごとの移行状況、古い権限の拒否確認、影響調査へ渡した対象と未確認の範囲を残します。認証情報の値や秘密鍵を、チケット、ログ、通知、テストデータへコピーしません。

提供元への照会が失敗した、ログが途中までしか取れない、通知が届かない場合は、それぞれ未解決として扱います。新しい認証情報の成功や模擬テストの合格を、実際の失効や影響なしの証拠にしません。

投稿の削除、Git履歴の書き換え、成果物の削除、デプロイの差し戻しは、証拠や業務を変えます。認証情報の失効と混ぜず、影響を調べてから別に判断します。

提供元と認証情報の種類が決まり、失効の単位・関連セッション・安全な確認方法を確かめられる場合だけ限定実装を検討します。共通の失効スクリプトは置きません。

## 診断で確認する項目（異常時テスト）

- 新しいトークンで処理が動いただけで、古いトークンや既存セッションも使えなくなったと判断していないか。
- 主な処理だけを更新し、緊急用の処理や別の利用先に古い権限が残っていないか。新しい権限を以前より広げていないか。
- ログが0件でも、必要な期間や操作を調べられなかった場合に「悪用なし」としていないか。
- 失効や調査が未確認なのに対応を閉じたり、認証情報の値を記録や通知にコピーしたりしていないか。

これらは机上演習や診断で使う確認項目であり、実際の認証情報を失効・検査した記録ではありません。

## フレームワークとの関係

- MITRE ATT&CK v19.1 **T1078（Valid Accounts）**の継続的な悪用を抑える設計と部分的に関係します。漏れた認証情報と残る権限を止める点が対応します。実際の失効・セッション停止や、すべての不正利用の検知を示すものではありません。

対応する特性と限界は[マッピング](../../../../mappings/frameworks.yaml)に記録しています。ATT&CKは攻撃手法の分類であり、準拠基準ではありません。

## このコントロールの範囲

対象は、開発・CI・公開・デプロイなどに使う認証情報の漏えいが疑われた後の封じ込めと影響調査への引き渡しです。普段の権限管理は[SOURCE-004](../../source-protection/psb-source-004-source-access-credential-lifecycle/README.md)、共有前の検査は[SOURCE-002](../../source-protection/psb-source-002-secret-publication-boundary/README.md)、公開情報からの発見は[SOURCE-003](../../source-protection/psb-source-003-public-source-exposure-triage/README.md)で扱います。成果物や稼働環境への最終的な対応は[GOV-001](../psb-gov-001-supply-chain-impact-assessment/README.md)などで判断します。このコントロールだけで、インシデント全体の復旧や悪用が一度もなかったことは証明できません。

非公開リポジトリへ誤って送った場面は[教材](learning.md)、認証情報の種類ごとに何を止め、どう安全に確かめるかは上の方式説明を参照してください。7つの特性と根拠のIDは[control.yaml](control.yaml)、資料の採否は[Sources](../../../../sources/README.md#ref-credential-exposure-containment-001)、フレームワークとの関係は[マッピング](../../../../mappings/frameworks.yaml)、旧成果物との対応は[移行記録](../../../../docs/MIGRATION_GOVERNANCE_OPERATIONS.md#credential-exposure-migration)にあります。

調査・対応・復旧のつなぎ方は[問題の発見から対応・再開まで](../../../../engineering/security-signal-to-response.md)を参照してください。
