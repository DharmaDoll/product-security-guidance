# PSB-GOV-010: External attack surface reconciliation

**自組織が責任を持つ公開サービスに、台帳にないものや意図しないものが見つかったら、担当者へ渡せるか。**

## なぜ必要か

たとえば廃止したはずの`preview.example.test`が外から見える。台帳にないなら調査が必要です。ただし、名前が委託先の共有基盤を指すだけで、そのIP全体を調べる権限があるわけではありません。

## 満たすべきこと

- 観測する範囲、自組織の管理責任、担当者、許可された確認方法を決める。
- 観測元、時刻、範囲、取得状態を記録する。収集失敗や一部だけの取得を「公開サービス0件」とせず、以前の候補も消さない。
- 候補の出所と帰属を確認し、自組織の名前、委託先、共有基盤、所有不明を区別する。
- 台帳にある期待する公開状態と照合し、未登録・意図しない公開・是正後の再出現を担当者へ渡す。一時的に見えなくなっただけで是正済みにしない。
- 能動的な確認は許可された対象と方法に限る。判断に不要な認証情報、応答本文、個人情報を保存・通知しない。

## 最初に決めること

| 判断 | 選択肢と代償 |
|---|---|
| 起点 | 管理するドメイン、クラウドアカウント、公開IPなどを責任の根拠と結ぶ。ドメイン起点だけならIPだけの公開資産を見落とす |
| 観測手段 | 証明書ログは過去の名前の候補、DNSは名前と参照先、クラウドAPIは管理下の設定、外部観測サービスは選んだ公開面の状態を示す。対象に応じて組み合わせ、全手段を一律に要求しない |
| 台帳 | 安定した資産ID、担当者、環境、意図した公開、期待するサービス、見直し期限を持つ。古い台帳との一致は合格ではない |
| 確認方法 | 受動的な照合から始め、能動的な通信は対象、方法、頻度、委託先との境界ごとに許可する |
| 結果の意味 | 観測された候補、正常に観測した範囲、未観測範囲を分ける。候補0件は全公開面の不在を証明しない |

## 帰属と照合の境界

外部データの名前は正規化しても、所有の証拠になりません。起点の所有確認、DNSや委託先への委任、管理台帳の担当者を突き合わせ、`自組織が管理する名前`、`委託サービス`、`第三者の共有基盤`、`未確定`を区別します。共有IPの発見を、IP全体へのスキャン許可へ拡張しません。

台帳との差分は少なくとも、未登録の候補、登録済みだが期待外の公開、見直し期限切れ、以前是正した候補の再出現に分けます。台帳にないことと悪意あることは同義ではありません。担当者の判断を通じて、資産登録、公開停止、委託先への確認、脆弱性診断の依頼へ送ります。

## 観測障害と状態

収集元ごとに照会範囲、時刻、ページやcursor、上限、最後の成功、収集失敗を残します。「収集APIは成功したが一部のページが欠けた」場合は得られた候補を捨てず、coverage不足も同時に伝えます。台帳取得、照合stateの保存、通知のいずれかが失敗した場合も、完了した正常観測と区別します。

状態の更新では、今回見えた候補の追加・変化と、今回見えなかった候補の扱いを分けます。部分取得でも新候補は調査へ送れますが、欠けた範囲の既存候補は消しません。収集元の成功だけでなく、照会した範囲・全ページの取得・台帳の取得が確認できた場合に限り、その範囲について「今回は見えなかった」と記録します。それでも非検出は公開停止の証拠ではなく、閉鎖には処置と許可された再観測が必要です。収集元や対象範囲が変わった回も、比較できない範囲を前回の正常結果で埋めません。

候補の識別は表示名だけに頼らず、名前、サービス、観測元、変化を追える参照を使います。是正済みと閉じるには、設定変更などの処置と、許可された手段での再観測を照合します。検索から消えたことだけを完了条件にしません。保存・通知は判断に必要な識別子と参照に絞り、応答本文や認証情報を複製しません。

## 実装を作る開始条件

実装例を作る際は、対象となる使い捨てのドメイン・クラウド環境または明示的に許可された外部収集元、台帳の正本、収集APIの版・契約、能動的確認の許可範囲、通知先を先に決めます。次に、正常な一致、未登録・期待外の公開、収集失敗または部分取得、再出現をその環境で観測し、導入と解除の最短手順を示します。旧Python verifier（`scripts/verify.py`）には照合ロジックがあるものの、collectorは同梱されず、旧profileも固定のため、そのまま実装例としては移しません。

## 診断で確認する項目（異常時テスト）

- 収集APIや台帳の取得失敗、途中までの取得、期限切れを正常な0件や全件一致にしていないか。
- 収集が一部だけ成功した回に、見えなかった既存候補を削除・是正済みにしていないか。
- 証明書ログに名前があるだけで現役のサービスと断定したり、DNSから消えただけで資産がなくなったと判断したりしていないか。
- 委託先の共有基盤を指す名前から、第三者のIP全体を無断でスキャンしないか。
- 未登録の公開や再出現を担当者へ渡し、不要な認証情報や応答本文を広めていないか。

これは設計レビューや診断で使う項目であり、実環境を調査した記録ではありません。

## フレームワークとの関係

このControlには、照合済みのフレームワーク対応をまだ登録していません。公開サービスの発見・帰属確認・台帳との照合という本文の判断を、特定の規格への準拠とは扱いません。参照資料の採否は[Sources](../../../../sources/README.md#ref-external-surface-001)、対応関係の正本は[マッピング](../../../../mappings/frameworks.yaml)にあります。

## このコントロールの範囲

対象は管理責任を確認した名前やサービスと、採用した観測手段で見える範囲です。観測した名前だけでは現在の稼働、所有、脆弱性は確定しません。公開ソースの情報漏えいは[SOURCE-003](../../source-protection/psb-source-003-public-source-exposure-triage/README.md)、既知対象の検査結果は[GOV-009](../psb-gov-009-scanner-evidence-trust-boundary/README.md)が扱います。実際の収集元、台帳、通知経路の導入は別途確認が必要です。
