# PSB-GOV-001: Supply-chain impact assessment

**問題のある依存パッケージは、どの製品・成果物・稼働環境に使われているか。**

## なぜ必要か

問題のある依存版が分かった後、影響する製品を特定し、対応を決める担当者へ渡すための調査です。たとえば、パッケージ名の検索だけでは、どのビルドに入り、どの成果物が今動いているかは分かりません。調べられなかった製品も明示します。

## 満たすべきこと

1. **対象をたどる。** 問題のある依存の正確な名前・版・取得元から、リポジトリ、ビルド、SBOM、成果物のdigestを照合する。SBOMがソースと完成物のどちらを表すか、取込み後の分析が終わったかも確認する。成果物に残らなくても、ビルド中に実行された依存は調査対象にする。
2. **稼働先を確かめる。** 実際に動いている成果物のdigest、環境、観測時刻を調べる。検索権限、全ページ、収集範囲と鮮度を確認し、「影響候補」「調べた範囲では該当なし」「調査不能」を分ける。
3. **判断へ渡す。** 担当者と未確認の範囲を残し、影響候補を[GOV-003](../psb-gov-003-vulnerability-priority-decision/README.md)の優先度判断へ渡す。証拠を残しつつ、削除や失効など影響の大きい操作は担当者と承認条件を決めてから行う。切迫した被害への対応を、全証拠の収集まで無期限に待たせない。

<a id="failure-checks"></a>

## 診断で確認する項目（異常時テスト）

- ソースのSBOMで検索0件でも、完成物の収集範囲を確認せず製品全体を「影響なし」にしていないか。
- SBOMの取込みが済んだだけで分析完了とみなし、検索0件を非該当にしていないか。
- 検索権限不足、次ページの未取得、稼働状況の収集失敗を結果から消していないか。
- 可変のタグやリリース名だけで稼働先を決め、実際のdigestと観測時刻を確認し忘れていないか。
- 調査不能な対象を、理由と担当者なしで「影響なし」や低優先度へ渡していないか。

これらは確認項目であり、実際の製品調査や対応の結果ではありません。

## フレームワークとの関係

- NIST SSDF 1.1 **RV.1.1**を部分的に支えます。問題のある部品を正確な成果物・稼働先に結び付け、調べられない範囲を残す点です。脆弱性情報の継続収集や全報告の調査完了までは扱いません。
- NIST SSDF 1.1 **RV.2.1**を部分的に支えます。製品ごとの該当性と未確認範囲を対応計画へ渡す点です。優先度やリスク対応の決定・実行は別の判断です。

対応する特性と限界は[マッピング](../../../../mappings/frameworks.yaml)に記録しています。実際の影響調査や準拠を示すものではありません。

## このコントロールの範囲

対象は、問題のある依存から影響する製品・成果物・稼働先を探し、判断と初動計画へ渡すところまでです。依存が含まれているだけで悪用や侵害を証明するものではありません。[CI/CD Security](../../cicd-security/README.md)はCIの処理と権限を守り、[REL-003](../../release-integrity/psb-rel-003-release-sbom-identity-and-analysis/README.md)はSBOMの取得地点と成果物・稼働先との対応を整えます。GOV-001は、その記録を問題発覚後の影響調査に使います。復旧の完了は[GOV-005](../psb-gov-005-deployed-artifact-recovery/README.md)で別に確認します。

検索0件の考え方は[教材](learning.md)、調査範囲・外部分析基盤・初動計画の選び方は[engineering](../../../../engineering/governance-operations/incident-impact-and-response-planning/README.md)を参照してください。7つの特性と根拠のIDは[control.yaml](control.yaml)、資料の採否は[Sources](../../../../sources/README.md#ref-supply-chain-impact-001)、フレームワークとの関係は[マッピング](../../../../mappings/frameworks.yaml)にあります。
