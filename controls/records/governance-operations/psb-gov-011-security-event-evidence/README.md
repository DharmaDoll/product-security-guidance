# PSB-GOV-011 Security event evidence

**不正操作が疑われたとき、何が起きて、どこまで影響したかを記録から調べられるか。**

## なぜ必要か

公開アプリへの攻撃を検知しても、その時刻のアプリや内部APIの記録がなければ、入口で止めたのか、内部まで操作されたのか分かりません。再起動でログが消えたり、侵害された権限で削除できたりすれば、後から調査できなくなります。

## 満たすべきこと

1. **調べたいことから記録を選ぶ。** 守るサービスと攻撃の場面ごとに、入口、アプリ、実行環境、通信、認証、管理操作の必要な記録と担当者を決める。取得できない情報も残す（EVENT-1）。
2. **操作と対象をたどれるようにする。** 主体、時刻、対象、操作、成否を必要に応じて記録し、実行環境や別サービスの情報と照合できるようにする。時刻やIPだけで同一人物・同一攻撃と断定しない（EVENT-2）。
3. **記録できていない状態に気づく。** 収集停止、遅延、項目欠落、対象漏れ、保存先の障害を担当者へ伝える。記録がない期間を「不正利用なし」にしない（EVENT-3）。
4. **必要な期間、守って使える状態にする。** 保存期間、検索方法、閲覧・変更・削除の権限を決める。侵害された実行環境から調査記録まで消されないようにし、配送と保存を保護する（EVENT-4・5）。
5. **記録自体から情報を漏らさない。** token本体や不要な本文・個人情報を集めず、調査結果にも必要最小限を渡す（EVENT-6）。

## 診断で確認する項目（異常時テスト）

- 対象サービスを追加したとき、収集対象から外れたまま全体を監視済みとしていないか。
- 収集を止める、項目を欠かす、配送を遅らせると、検索0件と区別して担当者へ届くか。
- 実行環境を破棄しても必要な記録が残るか。侵害を想定したアプリ権限で保存済みの記録を削除・変更できないか。
- 異なる主体の同時刻の操作を混ぜないか。対象の識別が足りない場合は未確定と分かるか。
- 保存したはずの期間を担当者が検索できるか。権限不足や検索の部分失敗を「該当なし」にしないか。
- 無効な試験用tokenや機微情報を模した値を使ったとき、通知や共有用の記録へ不要に複製されないか。

確認項目であり、実サービスで試した結果ではありません。

## フレームワークとの関係

NIST SP 800-61 Rev.3のDE.AE-03（複数情報の関連付け）を、EVENT-2・5が部分的に支えます。ログの保存・保護・品質の設計入力は[共同ガイダンス](../../../../sources/README.md#ref-security-event-logging-001)です。保存期間や必須項目は採用環境で決めます。対応の範囲は[framework mapping](../../../../mappings/frameworks.yaml)、NISTの採否は[参照記録](../../../../sources/README.md#ref-security-operations-lifecycle-001)にあります。資料全体への準拠や導入済みを示しません。

## このコントロールの範囲

製品と開発基盤の調査に必要な記録を扱います。記録があっても検知できるとは限らず、検知と初動は[GOV-012](../psb-gov-012-detection-and-response-readiness/README.md)へ渡します。認証情報そのものの管理は[SOURCE-004](../../source-protection/psb-source-004-source-access-credential-lifecycle/README.md)、コンテナセンサーの具体的な観測範囲は[CONTAINER-004](../../container-cloud-iac-security/psb-container-004-runtime-threat-detection/README.md)の責任です。

[教材](learning.md)で調査の場面を読み、[記録の設計](../../../../engineering/security-event-collection-and-investigation.md)で収集・保存方式を選びます。[特性と根拠](control.yaml)から各条件を追えます。
