# PSB-GOV-005: Deployed artifact recovery

**影響を受けた稼働中の成果物を置き換え、古い成果物がもう動いていないと確かめられるか。**

たとえば、問題のあるコンテナイメージを再ビルドして同じタグで公開しても、別の地域では古いイメージが動いているかもしれません。ビルドや配布の成功と、元の調査範囲から古いものが消えたことは別に確認します。

## 満たすべきこと

1. **対象と期限を決める。** 影響を受ける成果物を変更されない識別子（digest）で特定し、どの環境で動いているか、停止中でも再起動できるかを調べる。担当者と対応期限を決め、脆弱性なら[GOV-003](../psb-gov-003-vulnerability-priority-decision/README.md)の期限を引き継ぐ。
2. **正しい置換先を作る。** 原因を再び取り込まない方法で、レビューした変更から別のdigestを作る。ソース、ビルド、署名、SBOM、公開判断が同じ新しい成果物を指すか確認する。別digestになっただけで問題が修正されたとは判断しない。
3. **実際の稼働を確かめる。** 置き換える環境では、許可された新しいdigestが実際に動いているか確かめる。廃止する環境では停止と再起動経路を確認する。元の調査範囲を再び調べ、古いdigestが動いておらず、切り戻しでも戻らないことを確認する。

一部の環境を調べられない、観測が古い、通知が失敗した場合は復旧済みにしません。旧成果物の一時使用を例外で認めても、元の期限や未完了の状態を消しません。

<a id="failure-checks"></a>

## 診断で確認する項目（異常時テスト）

- 新しいタグやビルド成功だけで、実際には同じdigestや未修正の成果物を復旧済みとしていないか。
- 署名やSBOMが、配布・稼働する新しいdigestとは別の成果物を指していないか。
- 一つの環境だけを更新して、別の地域、停止中の処理、切り戻し先に古いdigestを残していないか。
- 稼働状況の取得失敗や一覧からの消失を、古いdigestが動いていない証拠にしていないか。
- 一時使用の例外や期限超過を、復旧完了に置き換えていないか。

これらは机上演習や診断の確認項目であり、本番環境で置換した記録ではありません。

## このコントロールの範囲

対象は、影響すると判断された稼働成果物の再構築、置換、旧成果物の非稼働確認です。製品への影響調査は[GOV-001](../psb-gov-001-supply-chain-impact-assessment/README.md)などから受け取り、脆弱性の修正を主張する場合は[GOV-008](../psb-gov-008-vulnerability-remedy-validation/README.md)の検証結果を別に使います。新しい成果物にも未知の問題は残り得ます。

具体的な場面は[教材](learning.md)、ビルド・公開・各環境での確認方法は[engineering](../../../../engineering/governance-operations/deployed-artifact-recovery/README.md)を参照してください。7つの特性と根拠のIDは[control.yaml](control.yaml)、資料の採否は[Sources](../../../../sources/README.md#ref-deployed-artifact-recovery-001)、フレームワークとの関係は[マッピング](../../../../mappings/frameworks.yaml)、旧成果物との対応は[移行記録](../../../../docs/MIGRATION_GOVERNANCE_OPERATIONS.md#deployed-artifact-recovery-migration)にあります。
