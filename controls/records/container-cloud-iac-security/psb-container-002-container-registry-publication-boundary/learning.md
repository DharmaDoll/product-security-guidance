# 学習：レジストリに残すことと、使用を止めること

対応するcontrol：[PSB-CONTAINER-002 Container registry publication boundary](README.md) · 設計：[Container registry publication and lifecycle](../../../../engineering/container-cloud-iac-security/container-registry-publication-and-lifecycle/README.md)

## 問題のあるイメージを消すべきか

架空の場面です。公開済みイメージに問題が見つかり、担当者はその内容を識別するハッシュ値（digest）を指定して、使用停止の状態（`quarantined`）にしました。調査と切り戻しの判断に必要なため、イメージを保管・配布するレジストリ上の内容と公開記録は残します。別の利用者は古いタグや複製先から同じイメージを取得できます。レジストリに残すという判断と、新しい実行を許すという判断は同じではありません。

レジストリでは、誰がどの保管先へ公開・変更・削除できるかを制限し、公開した内容をdigestで識別します。タグは人が見つけやすい名前ですが、別の内容へ付け替えられる場合があります。OCI形式で複数のOS・CPU向けイメージをまとめて配布する場合、一覧（image index）と各環境向けの構成情報（manifest）には別々のdigestがあります。公開記録にはどちらを指すかも残します。

## 状態名だけでは決められない

`active`、`deprecated`、`quarantined`、`removed`は運用上の状態名です。例えば非推奨を表す`deprecated`でも、期限付きの切り戻しに許す設計はあります。一方、使用停止と決めた`quarantined`は、イメージ本体が残っていても[使用直前の許可](../psb-container-001-deployment-artifact-admission/learning.md)で拒否する必要があります。状態と使用可否、対象、期限、判断根拠を別に記録します。これらの名前が、すべてのレジストリに共通する機能として備わっているという意味ではありません。

削除だけではキャッシュや複製先、既に稼働中の環境まで止められません。[GOV-005の復旧判断](../../governance-operations/psb-gov-005-deployed-artifact-recovery/learning.md)には、新旧イメージのdigestと、修正版の公開・旧版の使用停止の状況を渡します。稼働先に旧版が残っていないかは別に観測します。状態の通知や稼働状況の収集が途切れたときも、「もう使われていない」とは結論しません。

この場面では、まず使用停止の対象をdigestで特定し、利用先で新しい起動を拒否できるようにします。調査用に残す内容へのアクセスは必要な担当者に絞ります。レジストリ上で状態を変更できても、利用先へ届いたか分からなければ、使用停止の確認は終わっていません。

## 修正版を公開する権限は、旧版を書き換える権限か

同じ場面で、修正版を公開するCIジョブに、過去のリリースのタグ変更・削除や保護設定の変更まで許されていたとします。このジョブの認証情報が盗まれると、攻撃者は修正版を置くだけでなく、既存のリリース名を別の内容へ向けたり、調査対象を消したりできます。利用者が信じている公開済みの名前や記録を、公開用の権限で壊せてしまう構成です。

そこで、公開ジョブには対象の保管先と必要な操作だけを許し、公開済み参照の保護や削除の判断を分けます。修正版は新しいdigestとして公開し、承認した内容と公開先が一致することを確認します。旧版の公開記録を修正版の内容へ書き換えて、対応が終わったように見せてはいけません。誰が、何を、いつ変更し、成功したかを追える記録も必要です。

判断を整理すると、レジストリへの登録成功は「保存できた」、リリースとしての公開は「承認した内容を利用者へ提供する」、使用許可は「その環境で起動してよい」という別の判断です。公開先が正しくても内容の検証は残り、使用停止にしても調査のための保持はできます。公開権限、保護設定、保持方法の選択肢は[設計パターン](../../../../engineering/container-cloud-iac-security/container-registry-publication-and-lifecycle/README.md)で扱います。

採用先で試す項目は[controlの診断観点](README.md#failure-checks)、資料の採否は[Sources](../../../../sources/README.md#ref-container-registry-publication-001)にあります。
