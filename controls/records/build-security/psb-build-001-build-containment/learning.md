# 学習：依存を承認しても、実行権限は別に制限する

[コントロール記録](README.md) · [設計パターン](../../../../engineering/build-security/build-execution-boundary/README.md)

## 一つの依存更新から考える

開発者が依存更新をレビューし、ロックファイルとハッシュを固定しました。ビルドジョブは承認済みのファイルを取得します。
しかし、そのパッケージのテスト用プラグインが、実行時に環境変数を読み、外部へ送信しようとします。
ハッシュが一致しても、この行動は止まりません。このジョブには公開用トークンも渡されており、プラグインから利用できる状態です。

取得する内容を決める判断と、取得したコードに何をさせるかという判断は別です。
ビルド対象に含まれるコードを「build code」、ビルド基盤を管理・公開する権限を「build authority」と呼び、同じ場所へ置かないようにします。

## この場面ではどう判断するか

このジョブは「承認したファイルを使った」だけでは公開工程へ進められません。プラグインがトークンを読めたか、
どの宛先へ通信できたか、生成した成果物が後続へ渡されたかを確認します。通信ログがないだけで
「送信されなかった」とは判断しません。トークンの漏えいが疑われる場合の封じ込めと利用履歴の調査は
[GOV-004](../../governance-operations/psb-gov-004-credential-exposure-containment/README.md)へ渡します。

次のビルドでは、認証が必要な依存の取得を、プラグインが動く前に別の境界で済ませます。固定して照合した入力だけを
一時的なビルド環境へ渡し、公開・デプロイ用トークン、クラウド権限、ホストの管理ソケットをその環境に置きません。
書き込める場所と通信先も必要な範囲へ絞り、通信の拒否はビルド中のコードが変えられない外側で強制します。
必要な取得先への通信を許す場合も、そこへ任意の情報を送ってよいという許可にはしません。

ビルドが終わったら、出力を識別して別の公開処理へ渡します。公開側はビルドが出した設定や命令をそのまま高権限で
実行せず、期待する成果物と対象を独立して確認します。観測の停止やログ配送の失敗でビルド中の行動を確認できないなら、
正常にファイルができても自動で公開へ進めません。隔離は権限悪用の経路を狭めますが、成果物へ悪意あるコードを
混ぜる経路まで消すものではありません。この場面は説明用であり、実際のビルド環境で拒否を確認した結果ではありません。

## 攻撃経路をどこで切るか

```text
承認した依存 → pluginを実行 → jobの資産や権限を取得 → 外部送信／公開先変更
                  ↓
       秘密情報なし・限定入力・隔離・通信拒否
                  ↓
       固定した出力 → 別consumerが独立して受入判断
```

秘密情報を渡さず、hostの管理経路へ届かせず、入力取得後の通信も閉じれば、上の直接的な権限悪用・送信経路は狭まります。
一方、生成した成果物へ悪意あるコードを埋める経路は残ります。Digestや署名はその成果物の同一性を確認するもので、無害性の判定ではありません。

## 三つの直感を見直す

| 直感 | 見落とす境界 |
|---|---|
| 新しいrunnerなら安全 | 実行中に渡したtokenやmetadataへの到達性は、終了後の破棄では取り消せない |
| allowlistの宛先なら安全 | 許可したregistryやproxyへも、不要なデータを送れる場合がある |
| sensorにイベントがないなら安全 | 停止・欠落・配送障害なら行動を観測できない。Healthの確認が必要 |

Sensorは行動を知る手段、sandboxや通信制御は行動の可能性を制限する手段です。
センサーが動いても通信を拒否した証拠にはならず、拒否できてもログが届くとは限りません。

## レビューで確認する問い

どのコードがいつ実行され、どのファイル、token、socket、宛先へ届くかを実行環境から確認します。
取得サービス・provisioner・sensorに必要な権限は、ビルド対象のコードへ渡さない構造にします。
無害な拒否試験の結果と外側の制御ログを照合し、観測できなかった部分は未確認として残します。

[REF-PORTFOLIO-001](../../../../sources/README.md#ref-portfolio-001)ではplatformと外部依存からoperationsへの受け渡しを考える教材です。
[攻撃段階の索引](../../../../docs/ANALYSIS_LENSES.md)の7を直接扱い、8の来歴、9の署名・consumer判断、12の調査へ責任を残します。
上のシナリオはリポジトリでの解釈であり、特定の事件・製品の動作報告ではありません。
