# PSB-DETECT-003: External attack surface reconciliation

**自組織が責任を持つ公開サービスに、台帳にないものや意図しないものが見つかったら、担当者へ渡せるか。**

## なぜ必要か

たとえば廃止したはずの`preview.example.test`が外から見える。台帳にないなら調査が必要です。ただし、名前が委託先の共有基盤を指すだけで、そのIP全体を調べる権限があるわけではありません。

## 満たすべきこと

- 観測する範囲、自組織の管理責任、担当者、許可された確認方法を決める。
- 観測元、時刻、範囲、取得状態を記録する。収集失敗や一部だけの取得を「公開サービス0件」とせず、以前の候補も消さない。
- 候補の出所と帰属を確認し、自組織の名前、委託先、共有基盤、所有不明を区別する。
- 台帳にある期待する公開状態と照合し、未登録・意図しない公開・是正後の再出現を担当者へ渡す。一時的に見えなくなっただけで是正済みにしない。
- 能動的な確認は許可された対象と方法に限る。判断に不要な認証情報、応答本文、個人情報を保存・通知しない。

<a id="failure-checks"></a>

## 診断で確認する項目（異常時テスト）

- 収集APIや台帳の取得失敗、途中までの取得、期限切れを正常な0件や全件一致にしていないか。
- 収集が一部だけ成功した回に、見えなかった既存候補を削除・是正済みにしていないか。
- 証明書ログに名前があるだけで現役のサービスと断定したり、DNSから消えただけで資産がなくなったと判断したりしていないか。
- 委託先の共有基盤を指す名前から、第三者のIP全体を無断でスキャンしないか。
- 未登録の公開や再出現を担当者へ渡し、不要な認証情報や応答本文を広めていないか。

これは設計レビューや診断で使う項目であり、実環境を調査した記録ではありません。

## フレームワークとの関係

このControlには、照合済みのフレームワーク対応をまだ登録していません。公開サービスの発見・帰属確認・台帳との照合という本文の判断を、特定の規格への準拠とは扱いません。参照資料の採否は[Sources](../../../../sources/README.md#ref-external-surface-001)、対応関係の正本は[マッピング](../../../../mappings/frameworks.yaml)にあります。

## このコントロールの範囲

対象は管理責任を確認した名前やサービスと、採用した観測手段で見える範囲です。観測した名前だけでは現在の稼働、所有、脆弱性は確定しません。公開ソースの情報漏えいは[SOURCE-003](../../source-protection/psb-source-003-public-source-exposure-triage/README.md)、既知対象の検査結果は[DETECT-001](../psb-detect-001-scanner-evidence-trust-boundary/README.md)が扱います。実際の収集元、台帳、通知経路の導入は別途確認が必要です。
