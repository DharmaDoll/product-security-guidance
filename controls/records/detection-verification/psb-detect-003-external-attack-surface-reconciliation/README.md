# PSB-DETECT-003 External attack surface reconciliation

## 問い

自組織が責任を持つ外部公開サービスについて、外から観測した候補を管理台帳と照合し、知らない公開・意図しない公開・再出現を担当者へ渡せるか。

## できてはいけないこと

未登録の公開サービスが見つかっても所有者不明のまま放置されること、観測が失敗した期間を「新しい公開なし」と報告すること、自社のドメイン名が指す第三者の共有基盤まで調査権限があるとみなすことを防ぎます。資産台帳と外部観測の不一致は調査の入口であり、それだけで脆弱性を確定しません。

## 起点となるシナリオ

廃止したはずの`preview.example.test`が、委託先の共有サービスを指したまま外部から見えています。台帳には載っておらず、以前の是正記録には同じ名前があります。名前の観測だけで委託先のIP全体をスキャンすると、許可範囲を越えます。逆に収集APIの期限切れで結果が0件になったことを「是正済み」と扱えば、再公開を見逃します。

守る資産は、公開サービスの把握、担当者への引き渡し、許可された調査範囲です。公開面から候補を観測しても、自組織の所有、現在の稼働、脆弱性は別々に確認します。

## 適用範囲

所有・管理責任を確認したドメイン、外部公開サービス、委託サービスと、その範囲について採用した観測手段に適用します。証明書ログ、公開DNS、クラウド台帳、許可された外部観測サービスなどは候補であり、どれも単独で全公開面の網羅を保証しません。ドメインに結び付かない公開IPや別のクラウド資産は、採用する台帳と収集手段に含めた場合だけ対象です。

公開ソースの情報漏えいは[SOURCE-003](../../source-protection/psb-source-003-public-source-exposure-triage/README.md)、既知対象の脆弱性検査の証拠は[DETECT-001](../psb-detect-001-scanner-evidence-trust-boundary/README.md)が扱います。このcontrolは探索や検査の無制限な実行許可を与えません。

## 必要なセキュリティ特性

| ID | 満たすべき状態 |
|---|---|
| `EASM-1` | 観測対象の起点、管理責任の根拠、担当者、見直し時期と、許可する収集・確認方法を明示する |
| `EASM-2` | 観測結果に収集元、範囲、時刻、取得状態、欠落範囲を結び、部分取得・期限切れ・収集失敗を0件の正常結果から分ける |
| `EASM-3` | 候補の名前やサービスと元の観測を結び、組織の管理する名前、委託先、共有基盤、所有不明を区別して帰属を確認する |
| `EASM-4` | 台帳上の期待する公開状態・サービス・担当者と外部観測を照合し、未登録と意図しない公開を調査対象にする |
| `EASM-5` | 候補の継続・変更・是正後の再出現を追跡し、観測からの消失だけで是正完了にしない |
| `EASM-6` | 能動的な確認は対象と方法ごとの許可に限定し、ドメイン名の帰属から第三者IPや共有基盤全体への調査権限を推定しない |
| `EASM-7` | 保存・通知する証拠を担当者が判断できる範囲に絞り、認証情報、応答本文、不要な個人情報などを広く複製しない |

## 実装判断の羅針盤

台帳の名前と外部の名前が一致しても、委託先サービスや共有IPの所有は確定しません。観測手段は対象に合わせて選び、各手段が何を見ていないかを結果に残します。証明書ログに名前があることは現在の稼働を、DNS応答がないことは資産の消滅を、それぞれ証明しません。

新しい候補や期待と違う公開は所有者と運用担当へ渡します。脆弱性の判断は対象と権限を再確認して別の診断へ渡し、現に公開されているサービスの優先順位は[脆弱性対応判断](../../governance-operations/psb-gov-003-vulnerability-priority-decision/README.md)に引き継ぎます。観測障害は公開上のfindingと別に知らせます。

## 診断で確認する項目（異常時テスト）

以下は設計レビューや脆弱性診断で確認する項目です。本PJで実環境に対する試験を行った記録ではありません。

- 所有根拠が期限切れ、または担当者不明のドメインを、調査対象として無条件に追加できないか。
- 証明書ログだけの過去の名前を、現在稼働するサービスとして確定していないか。
- DNSのCNAMEやA/AAAAが第三者の共有基盤を指すとき、そこへの能動的なスキャンを自動で始めないか。
- 収集APIの失敗、ページ欠落、上限到達、期限切れ、台帳更新失敗を、正常な候補0件に変換していないか。
- 台帳にない名前や期待外の公開を、所有者未確定や別名を理由に通知せず閉じていないか。
- 是正済み候補が再び見えたときに新しい調査へ戻り、検索結果からの一時的な消失だけで閉じていないか。
- 応答本文、認証情報、不要なIP・個人情報がログや通知へ流れていないか。
