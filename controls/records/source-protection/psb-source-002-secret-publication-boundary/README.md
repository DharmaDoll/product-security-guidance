# PSB-SOURCE-002: Secret publication boundary

開発者が認証情報を含むファイルをコミットし、次のコミットで値を削除してからpushしたとします。
最新のファイルだけを検査すると、過去のコミットに残った値が共有リポジトリへ届きます。
このコントロールは、検査する内容と、コミット・送信・受入・mergeのどこで止めるかを対応付けます。

## 問いと直接の失敗

| 項目 | 内容 |
|---|---|
| 読者・問い | 開発者、リポジトリ管理者、診断担当者が、どの秘密情報をどの公開経路で検査し、拒否できるかを説明できるか |
| 守る資産 | ソースやGitのメタデータへ混入する認証情報・秘密鍵と、その値で到達できるサービス |
| 脅威・障害 | 誤ったステージング、ツールによる機密値の混入、hooksの省略・変更、検査範囲の欠落、スキャナーの障害 |
| できてはいけないこと | 定義した検出対象を含む変更、または必要な検査が完了していない変更を、検査済みとして指定した境界より先へ進める。ローカル検査の省略を受信側で無条件に信頼する |
| 適用範囲 | Gitのファイル・コミットメッセージ・導入履歴と、それらを共有する経路。対象ref、メタデータ、外部格納物、検出可能な形式を明記する |
| 非適用 | 全機密データの自動分類、認証情報の保管・失効そのもの、署名による作成者確認、公開済みコピーの回収、悪意ある利用者によるあらゆる持ち出しの阻止 |

ローカルhooksは早期に誤りを知らせる境界です。利用者が省略できる検査を、共有先の独立した受入判断の代わりにはしません。
受信側で拒否できても、受信処理にはデータが届きます。送信前の拒否、共有refへの受入拒否、送信後のmerge拒否を区別します。

## セキュリティ特性

| ID | 満たすべき状態 |
|---|---|
| SECRET-1 | 守る秘密情報、公開経路、対象ref・内容・履歴、検査不能な形式と拒否境界を定義する。対象外や省略した入力を検出なしに含めない |
| SECRET-2 | コミットやpushで実際に導入する内容に検査を結び付ける。作業ツリーだけ、最新コミットだけ、古い検査結果だけで許可しない |
| SECRET-3 | 実行するhook・検査器・ルール・除外設定の版と変更責任を管理する。検査対象の変更自身が、受信側の必須検査を無審査で弱められないようにする |
| SECRET-4 | 検出あり、検出なし、実行・取得・解析失敗、検査未完了を区別する。指定した拒否境界で、必要な検査の失敗や欠落を許可へ変換しない |
| SECRET-5 | ローカルhooksが省略されても共有先の受入制御を維持する。Web UI、API、bot、mirror等の経路と例外権限を確認し、受入前に検査できない経路は利用制限等の代替を定める |
| SECRET-6 | 検出値を端末出力、CIログ、レポート、通知へ再掲しない。調査に必要な最小限の位置・ルール・対象識別情報を、閲覧範囲を限定して残す |
| SECRET-7 | 誤検知の除外や例外を、対象・ルール・内容・期限・承認へ限定する。変更後の内容や別の履歴へ流用せず、障害・範囲不明を例外で検出なしに変えない |

根拠は[Gitと公開境界の参照資料](../../../../sources/README.md#ref-secret-publication-001)と
[OpenSSF OSPS Baseline](../../../../sources/README.md#spec-openssf-osps-20260219--openssf-osps-baseline)です。
独立した受入、検査対象との結合、例外の範囲は本PJで具体化した設計判断です。

## 診断で確認する項目（異常時テスト）

次は、秘密情報の混入や検査の迂回を実際に拒否できるか確認する項目です。本PJがすべてを試した結果ではありません。
試す場合は未発行の無害な検出用文字列を使い、実際の秘密情報を診断資料へ入れません。

- **SECRET-1・2**：秘密情報をステージした後、作業ツリーだけ修正すると、ステージ済みの値が検査を通らないか。
- **SECRET-2**：過去コミットへ追加した値を最新コミットで削除しても、新たに導入する履歴の検査が拒否するか。コミットメッセージにだけ含む値を見逃さないか。
- **SECRET-1・2**：新規ブランチ、複数ref、タグ、履歴書換えで検査範囲が欠落しないか。履歴不足や取得失敗を空の差分と誤認しないか。
- **SECRET-1・4**：サイズ上限、バイナリ、アーカイブ、LFS等の外部格納物を無言で読み飛ばして検出なしにしないか。拡張子の変更や例示用ファイル名だけで内容検査を免除しないか。
- **SECRET-3・5**：hooks未導入、実行権限の欠落、`--no-verify`、`core.hooksPath`の変更でローカル検査を省略しても、受信側で対象の混入を拒否できるか。
- **SECRET-3**：同じ変更で検査器・ルール・除外設定を弱めると、その変更が自分自身を許可できないか。未レビューのブランチにあるhookを自動実行していないか。
- **SECRET-4**：検査器不在、タイムアウト、不正出力、未知の終了状態、CIの欠落・取消を許可扱いしないか。
- **SECRET-5**：Web UI、API、bot、mirror、例外権限による書込みが、想定した受入検査の対象から外れていないか。CIで拒否した時点で既に保存された内容を未送信扱いしていないか。
- **SECRET-6**：検出・例外申請・デバッグ出力・異常終了時に、検出値や秘密を含む行全体を表示していないか。
- **SECRET-7**：特定の検出への承認が、別の値、変更後のコミット、別ref、期限後の操作へ再利用されないか。広い除外や自己承認で必須検査を無効にできないか。

## 実装判断の羅針盤

まず送信先にデータを渡す前に止める必要があるか、共有refへの受入を止めるか、mergeを止めるかを決めます。
[Secret checks before publication](../../../../engineering/source-protection/secret-checks-before-publication/README.md)で、Git hooks・受信側検査・CIの配置と代償を比較します。
検出対象の種類と未検査範囲を示し、代表的な文字列を検出できることを、全秘密情報の不在へ一般化しません。

## 残る責任と限界

分割・符号化された値や組織固有の機密情報は検出できないことがあります。意図的な持ち出し、侵害端末、外部送信全体は別の境界です。
認証情報の保管・失効は[SOURCE-004](../psb-source-004-source-access-credential-lifecycle/README.md)、検査器の取得と結果の信頼性は[DETECT-001](../../detection-verification/psb-detect-001-scanner-evidence-trust-boundary/README.md)へ接続します。
共有先へ到達した値は露出候補として所有者に渡し、失効・利用履歴の調査を進めます。履歴からの削除だけで、fork・clone・ログ等のコピーや認証情報の効力は取り消せません。
