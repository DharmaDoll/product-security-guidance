# PSB-SOURCE-007: Developer credential storage

開発者がクラウドへ接続するための長期トークンを、作業中のリポジトリの`.env`に保存したとします。Gitへ追加しなくても、そのファイルを読める拡張、テスト、開発agent、バックアップに値が渡る可能性があります。このcontrolは、**開発端末で使う実際の認証情報をどこに置き、どの処理へ渡すか**を決めます。

## 問いと範囲

読者は開発者、端末・開発環境の管理者、Product Security担当者です。守るものは、Git、クラウド、package registry、社内APIなどへ接続できる開発者のトークン、秘密鍵、パスワード、派生したセッションです。攻撃者は端末で動く悪意あるコードや拡張、または作業領域・バックアップのコピーを得た人です。

**問い**：再利用できる実際の認証情報が作業領域の平文ファイルに残らず、必要な処理だけが必要な時間に使えるか。

**できてはいけないこと**：`.env`、シェル設定、コマンド履歴、テスト出力などから、別の処理が開発者の認証情報を読み、本人の意図しない操作へ再利用できる状態を放置すること。

対象は開発者端末と、端末から利用する遠隔開発環境での保管・受け渡しです。検証用の無効なダミー値は対象外です。ソース管理サービス側の権限・失効は[SOURCE-004](../psb-source-004-source-access-credential-lifecycle/README.md)、端末の暗号化・更新・監視は[SOURCE-001](../psb-source-001-developer-endpoint-trust/README.md)、コミットやpushの検査は[SOURCE-002](../psb-source-002-secret-publication-boundary/README.md)で扱います。AI agentのtool操作を許可するかは[AI-004](../../ai-development-security/psb-ai-004-development-agent-runtime-boundary/README.md)の責任です。

## 満たすべきこと

| ID | 判断・確認すること |
|---|---|
| LOCAL-CRED-1 | 開発に使う認証情報の種類、所有者、利用する処理、保管場所を把握する。Git用だけを確認して、クラウドやpackage registry用を見落とさない |
| LOCAL-CRED-2 | 再利用できる実際の認証情報を、リポジトリの`.env`、設定ファイル、スクリプト、シェル設定などの平文の作業ファイルへ保存しない。承認したOSの資格情報保管機能や秘密情報管理サービスなど、アクセスを制限できる場所に保管する |
| LOCAL-CRED-3 | 保管場所から値を取り出す処理と、値を使う処理を決める。開発ツール、拡張、コンテナ、agentへ端末上の全認証情報を渡さず、必要な値と利用時間を絞る。環境変数や一時ファイルに渡す場合も、閲覧できる処理と残る場所を確認する |
| LOCAL-CRED-4 | コマンド引数、履歴、ログ、エラー表示、テスト成果物、作業領域のバックアップや同期先へ不要な平文コピーを残さない。用途終了後に残る一時的なコピーを把握し、削除または失効へつなぐ |
| LOCAL-CRED-5 | 既に平文ファイルや出力へ実際の値を置いた場合、ファイルの削除だけで終えない。共有・同期・バックアップ・実行履歴への広がりを確認し、認証情報の所有者へ失効と影響調査を渡す |
| LOCAL-CRED-6 | 利用するサービスが対応する場合は、端末に長く残る固定トークンを減らし、対話的な認証や短命な認証情報、持ち出せない鍵を選ぶ。長期の値が必要なら、用途・所有者・保管場所・見直す時点を決める |

ここでの強制点は保管先のアクセス制御、値を渡す仕組み、端末上で実行する処理の権限です。開発者の注意だけに任せず、承認した保管・取得方法を開発環境で使えるようにします。`.gitignore`やsecret scanは誤送信を減らしますが、端末でファイルを読める処理から値を守る手段にはなりません。方式の選択は[Developer credential storage and handoff](../../../../engineering/source-protection/developer-credential-storage-and-handoff/README.md)で扱います。

## 診断で確認する項目（異常時テスト）

以下はレビュー用のチェック項目です。実際の認証情報を使う試験や、本PJでの導入確認を示しません。

- 作業リポジトリの`.env`、設定ファイル、シェル設定、コマンド履歴に、再利用できる実際の値が残っていないか。`.gitignore`に載っているだけで保管を許していないか。
- 開発ツールへ一つの値を渡す際、無関係な拡張、子プロセス、コンテナ、agentにも読める形で渡していないか。
- デバッグ表示、失敗したテスト、端末のバックアップや同期先に値が残っていないか。取得できない範囲を「残っていない」と判断していないか。
- 平文の値を見つけた際、ファイル削除だけで対応を閉じず、影響する権限とセッションの所有者へ引き継げるか。
- 承認した取得方法が使えず、開発者が長期トークンを`.env`へ貼る以外に作業できない状態になっていないか。長期の値を使う場合、所有者と見直す時点が決まっているか。

## 判断の境界と読み進め方

ディスク暗号化は電源を切った端末の盗難には役立ちますが、ログイン済みの処理が読める`.env`を守りません。保管場所を変えても、その後に端末全体へ値を渡せば同じ問題が残ります。一方、認証情報を使う処理自体が侵害される場合や、提供サービス側の権限が広すぎる場合まで、このcontrolだけで防げるわけではありません。

[教材](learning.md)では`.env`から漏れる場面を追います。判断根拠は[参照資料記録](../../../../sources/README.md#ref-developer-local-credentials-001)、旧項目との関係は[端末移行記録](../../../../docs/MIGRATION_SOURCE_PROTECTION.md#endpoint-migration)にあります。組織への導入、端末上の実際の保管状態、漏えいの有無は確認していません。
