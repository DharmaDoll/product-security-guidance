# PSB-SOURCE-007 Developer credential storage

**開発端末の認証情報を平文の作業ファイルに残さず、必要な処理だけへ渡せるか。**

## なぜ必要か

例えば、クラウドのトークンをリポジトリ内の`.env`へ保存すると、Gitに追加しなくても、同じファイルを読める拡張、テスト、開発agent、バックアップへ値が広がります。`.gitignore`やsecret scanは、この端末内の読み取りを止めません。

## 満たすべきこと

1. **保管場所を決める。** Gitだけでなく、クラウド、package registry、社内APIなどの実際の認証情報について、所有者、使う処理、保管場所を把握する。再利用できる値を`.env`、シェル設定、スクリプトなどの平文作業ファイルに保存せず、アクセスを制限できる保管先を使う（LOCAL-CRED-1〜2）。
2. **渡す範囲を絞る。** 必要な処理へ必要な値だけを必要な時間に渡す。環境変数や一時ファイルを使う場合も、子プロセスや別のツールから読める範囲を確認する。コマンド履歴、ログ、テスト出力、同期・バックアップ先へ不要なコピーを残さない（LOCAL-CRED-3〜4）。
3. **長く残る値と露出を扱う。** 利用先が対応するなら短命なセッションや持ち出せない鍵を選ぶ。長期の値が必要なら所有者と見直す時点を決める。実際の値を平文で見つけたら、削除だけで終えず、広がった範囲と失効を所有者へ渡す（LOCAL-CRED-5〜6）。

## まず決めること

| 場面 | 判断すること |
|---|---|
| 保管 | OSの資格情報保管機能、承認済みの秘密情報管理サービス、対話的なログインなどから、対象の認証情報に合う方式を選ぶ。作業リポジトリの`.env`、シェル設定、スクリプトを実際の値の保管場所にしない |
| 長く残る値を減らす | サービスが対応する場合、固定トークンより対話的なログイン、短命なセッション、持ち出せない鍵を選ぶ。対応しない場合は、長期の値の用途・所有者・見直す時点を決める |
| 利用 | どのCLI・IDE・処理が、どの値を、いつ必要とするかを決める。ツール固有の認証連携が使えるなら、その受け渡し範囲を確認する |
| 一時的な受け渡し | 環境変数、標準入力、一時ファイルなどが必要な場合は、子プロセス・同一利用者の別処理・ログ・終了後の残存を確認する。環境変数を安全な保管庫と呼ばない |
| 遠隔・隔離環境 | 作業領域やホームディレクトリを丸ごと共有せず、必要な値と利用時間だけを選ぶ。遠隔環境の破棄と認証情報の失効を混同しない |

一例として、リポジトリには値のない`.env.example`だけを置きます。実際の値は承認した保管先へ置き、利用時に対象のCLIだけが受け取る経路を選びます。CLIが環境変数しか受け取らない場合も、端末全体で長く設定するのではなく、その呼出しに必要な範囲へ限定します。具体的なOSや製品の手順は、採用先が決まってから確認します。

組織の端末設定や開発環境の案内で、この取得方法を使えるようにします。「平文へ保存しないでください」と知らせるだけでは、代わりの作業経路がありません。

## 失敗しやすい経路

- `.gitignore`へ`.env`を追加しても、同じ端末の別処理やバックアップからの読み取りは止まりません。
- キーチェーンに保存しても、取り出した値をシェル設定へ書けば保管先を変えた意味がありません。
- OSの資格情報保管機能という名前だけで、同じ利用者の別アプリからの読み出しが拒否されるとは判断しません。採用する方式のアクセス設定を確認します。
- 環境変数は受け渡しに使えますが、継承した子プロセスや診断出力へ広がる場合があります。
- テスト用に発行した実際の短命な値も、期限が切れるまでは認証情報です。無効なダミー値と区別します。
- 既に値が漏れた疑いがあれば、ローカルファイルの削除だけで終えず、[Credential exposure containment](../../governance-operations/psb-gov-004-credential-exposure-containment/README.md)へ渡します。

開発agentへ渡す場合は、短命な認証キャッシュや更新元も含めて必要性を判断します。値を渡さない設計でも、agentが別の鍵を直接読める経路が残らないかは[AI-004の隔離設計](../../../../engineering/development-runtime-isolation.md#credential-operation-pairing)で確認します。読取り専用mountとSSOキャッシュの具体的な根拠は[一次資料の照合記録](../../../../sources/README.md#開発端末の認証情報保護に絞った追加照合2026-10-15)へ分けています。

確認では一つの作業について保管場所、値を受け取る処理、終了後に残る場所を図にします。実際の秘密値を記録せず、観測できないログ・バックアップ等は未確認とします。特定OSや秘密情報管理製品での拒否は未確認です。

## 診断で確認する項目（異常時テスト）

- `.env`、シェル設定、コマンド履歴に再利用できる実際の値が残っていないか。`.gitignore`だけで保管を許していないか。
- 一つのツールへ値を渡すとき、無関係な拡張、子プロセス、コンテナ、agentも読める状態になっていないか。
- デバッグ表示、失敗したテスト、バックアップ、同期先へ値が残っていないか。確認できない場所を「残っていない」と扱っていないか。
- 平文の値を見つけたとき、ファイル削除だけで終えず、認証情報の所有者へ影響調査と失効を渡せるか。
- 承認された取得方法が使えず、開発者が長期トークンを`.env`へ貼るしかない運用になっていないか。

これらは確認項目であり、実際の認証情報を使った試験や端末への導入結果ではありません。

## フレームワークとの関係

開発端末上の値の保管と処理への受け渡しについて、現行の[フレームワーク・マッピング](../../../../mappings/frameworks.yaml)に個別の関係は登録していません。参照資料にある保管方式を、特定規格への準拠や端末全体の安全性へ読み替えません。

## このコントロールの範囲

対象は開発者端末と、そこから使う遠隔開発環境における実際の認証情報の保管と受け渡しです。無効なダミー値は含めません。端末の暗号化・更新・監視は[SOURCE-001](../psb-source-001-developer-endpoint-trust/README.md)、ソース管理サービス側の権限・失効は[SOURCE-004](../psb-source-004-source-access-credential-lifecycle/README.md)、コミット・pushの検査は[SOURCE-002](../psb-source-002-secret-publication-boundary/README.md)、開発agentの操作認可は[AI-004](../../ai-development-security/psb-ai-004-development-agent-runtime-boundary/README.md)が扱います。保管先を変えても、認証情報を使う処理が侵害された場合や権限自体が広すぎる場合まで防げるわけではありません。

保管と受け渡しの方式は上の方式説明、`.env`から広がる場面は[教材](learning.md)を参照してください。６つの特性と参照資料IDは[control.yaml](control.yaml)、資料の採否は[Sources](../../../../sources/README.md#ref-developer-local-credentials-001)、旧項目との対応は[移行記録](../../../../docs/MIGRATION_SOURCE_PROTECTION.md#endpoint-migration)にあります。

前後の工程は[開発アクセスから漏えい対応・復旧まで](../../../../engineering/developer-access-to-recovery.md)で確認できます。
