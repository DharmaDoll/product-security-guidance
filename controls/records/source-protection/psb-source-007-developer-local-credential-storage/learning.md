# `.env`をGitに入れなければ十分か

[コントロール](README.md) · [設計パターン](../../../../engineering/source-protection/developer-credential-storage-and-handoff/README.md)

開発者がローカルの`.env`にクラウドのトークンを保存し、`.gitignore`へ追加しました。Gitのコミットには入りません。しかし、同じ作業領域で動く拡張やテストはそのファイルを読めます。作業領域を遠隔環境へ同期したり、端末のバックアップに含めたりすれば、コピーも増えます。

ここで守るのはファイル名ではなく、**その値を使ってできる操作**です。認証情報は、別の処理が取得すれば本人になり代わる材料になります。`.env`はアプリの設定を読み込む仕組みとして便利でも、認証情報専用の保管場所ではありません。`.gitignore`はGitへの追加を抑える設定で、ローカルの読み取りを防ぐ設定ではありません。

まず実際の値をどこで保管し、どの処理がいつ取り出すかを決めます。OSの資格情報保管機能や承認済みの秘密情報管理サービスは候補です。利用時に環境変数や一時ファイルへ渡すことはありますが、渡した先の子プロセス、ログ、終了後の残り方まで確認します。「保管先が安全」だけでは、利用中の広い受け渡しを説明できません。

開発環境に使いやすい取得方法がなければ、開発者は手元に長期トークンを貼り付けがちです。短い時間だけ使える認証や、秘密鍵を持ち出せない方式が対象サービスで使えるなら、端末に残す値そのものを減らせます。ただし短命な値でも、利用中に別の処理へ渡れば悪用され得ます。

## 保管庫へ移した後、誰に渡しているか

先ほどのトークンを保管庫へ移し、`.env`から削除したとします。開発者は作業の前に値を取り出し、シェルの環境変数へ設定してからIDEや開発agentを起動しました。この構成では、起動した処理やそこから動くテストへ値が引き継がれる場合があります。保管場所を変えても、受け渡しが広ければ、作業に不要な処理がトークンを使う経路は残ります。

例えば、agentにはソースの修正とローカルテストだけを任せ、クラウドへの反映は開発者が別に行う作業なら、agent側にクラウドの認証情報を渡す必要はありません。反映する処理だけが、承認した保管先から必要な権限を取得する形を考えます。agent自身に反映も任せるなら、対象と操作を制限する[AI-004の設計](../../ai-development-security/psb-ai-004-development-agent-runtime-boundary/README.md)へ進みます。

受け渡しの方法は、次のように見比べます。

| 変更したこと | まだ確認すること |
|---|---|
| `.env`から保管庫へ移した | どのアプリや処理が値を取り出せるか。取り出した値をログや設定へ残していないか |
| 長期トークンを短命な認証へ変えた | 利用中に誰が使えるか。更新に使うセッションやキャッシュまで他の処理へ渡していないか |
| 認証ディレクトリを読取り専用で共有した | 書換えを防いでも秘密は読める。作業に無関係な鍵やキャッシュを含んでいないか |

短命な認証キャッシュも、ただの作業用ファイルとは扱いません。新しい認証情報を得るために使うものなら、誰に読ませるかを決める必要があります。製品ごとの例と確認範囲は[公式資料との照合結果](../../../../sources/README.md#開発端末の認証情報保護に絞った追加照合2026-10-15)にあります。固定の有効期間や、認証ディレクトリ全体の共有を共通の推奨にはしません。

SOURCE-007では、値の保管先と受け渡す相手を決めます。実際にagentや子プロセスから別の鍵へ届かないようにする制限はAI-004で確認します。秘密の値を見せずに操作を代行する方式でも、代行先で何の操作を許すかは別に決めます。

## 既に置いていた値を片付ける

確認の順序は次のとおりです。

1. 値は本物か、無効なサンプルか。どのサービスの何の操作を許すか。
2. `.env`や作業領域に本物が残るか。誰とどの処理が読めるか。
3. 保管先から必要な処理だけへ渡せるか。渡した後にどこへ残るか。
4. 既に残った値なら、ファイル削除のほかに失効・セッション・同期先の確認が必要か。

この教材は[利用者提供資料と一次資料を使った本PJの解釈](../../../../sources/README.md#ref-developer-local-credentials-001)です。認証情報の権限と失効は[SOURCE-004](../psb-source-004-source-access-credential-lifecycle/README.md)、Gitへの混入は[SOURCE-002](../psb-source-002-secret-publication-boundary/README.md)で続けて確認します。

## この場面での判断例

- `.env`をGitへ追加していません。端末内で別の処理が読む問題も解消していますか。**いいえ。Gitへの混入と、端末内で読める範囲は別です。**
- 保管庫から取得した値を、agentを起動するシェル全体へ設定しました。必要な処理だけに渡せていますか。**まだ判断できません。継承する処理を確認し、不要な相手へ渡る経路を狭めます。**
- 短命トークンのキャッシュなので、作業フォルダと一緒に共有してよいでしょうか。**短命であることだけでは決められません。そのキャッシュで何ができ、誰が利用・更新できるかを確認します。**
