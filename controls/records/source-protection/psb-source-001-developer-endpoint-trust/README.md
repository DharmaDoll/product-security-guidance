# PSB-SOURCE-001: Developer endpoint trust

管理台帳には登録済みでも、更新と監視が停止した端末に開発用セッションが残っていると、侵害した攻撃者はソースを読み、変更できます。
このコントロールは、端末の保護基準と現在の状態を、業務資産へのアクセス判断へ結び付けます。

## 問いと直接の失敗

| 項目 | 内容 |
|---|---|
| 読者・問い | 端末管理者、Product Security担当者、業務資産の管理者が、どの端末に何を許可し、状態悪化時に何を制限するかを説明できるか |
| 守る資産 | 開発端末上のソース・作業データ・バックアップと、開発サービスに接続するセッション |
| 脅威・障害 | 盗難や放置端末の利用、悪意あるツール、過大な権限、更新・観測・設定配布の停止 |
| できてはいけないこと | 保護基準に違反する、紛失した、または状態が確認できない端末を、登録済みという理由だけで良好とし、定めた期限を越えて業務アクセスを維持する |
| 適用範囲 | ソースや開発サービスを利用する管理対象の開発者端末。遠隔開発環境を利用する場合の接続元端末も含む |
| 非適用 | 認証情報の発行・保管・失効自体、依存の採用、外部コードの実行隔離、公開時の内容検査、署名、製品自体のAI security |

信頼境界は、端末自身の申告から管理側の状態評価へ、状態評価から資産側のアクセス許可へ進む箇所です。
侵害端末からの自己申告や古い正常結果だけでは、この境界を越える根拠になりません。

## セキュリティ特性

| ID | 満たすべき状態 | 強制・判断する場所 |
|---|---|---|
| ENDPOINT-1 | 対象端末、所有者、利用資産、基準の版、観測元・時刻を対応付ける。未登録・古い観測・取得失敗を良好に変えず、拒否・制限・是正期限を決める | 端末管理基盤と資産側のアクセス制御 |
| ENDPOINT-2 | 保存領域の暗号化と回復鍵のアクセスを管理し、不在時の画面ロック・再認証、保管・輸送の基準を強制する | OS、鍵管理、端末の保管・利用手順 |
| ENDPOINT-3 | OS・開発ツールのサポート対象と更新期限を定め、再起動を含む適用状態を確認する。アプリ・拡張の採用と削除を管理し、未承認・期限超過を放置しない | 更新・アプリ管理と是正判断 |
| ENDPOINT-4 | 通常作業の権限を限定し、管理権限への昇格は目的・対象・時間を限定して記録する | OSと権限管理 |
| ENDPOINT-5 | 許可する通信と外部待受を定め、直接接続や代替経路で制御を迂回できないようにする。例外の公開範囲と期限を限定する | 端末・ネットワークの通信制御とサービスの待受設定 |
| ENDPOINT-6 | バックアップ対象、暗号化、鍵、復元権限、保持・削除を管理する。復元可能性と、復元時に古い認証情報を再配置しないことを確認する | バックアップと復旧の管理 |
| ENDPOINT-7 | 端末監視の登録・稼働・最終観測・通知・初動担当を分けて把握し、監視停止を検知ゼロと区別する | 監視基盤、通知先、端末管理者 |
| ENDPOINT-8 | 紛失・侵害時は対象と時間範囲を識別し、アクセス制限、既存セッション・認証情報の失効、調査へ引き継ぐ。到達確認のない隔離・消去を完了にせず、復旧状態を確認してアクセスを戻す | 端末管理者、資産・認証情報の所有者、インシデント担当者 |

特性の根拠は[端末管理の設計入力](../../../../sources/README.md#ref-developer-endpoint-baseline-001)です。
状態とアクセスを接続する具体的な判断は本PJの解釈であり、外部規格が固定の時間や製品を要求するという意味ではありません。

## Negative test：脆弱性診断のチェック観点

以下は診断観点であり、実施結果ではありません。テストコードがなくても、この観点の列挙で成立します。

- **ENDPOINT-1**：未登録端末、別端末の観測結果、古い正常結果を使って、管理対象の良好な端末としてアクセスできないか。
- **ENDPOINT-1**：状態取得が失敗した場合や是正・例外期限が切れた場合に、以前の許可を無期限に継続していないか。
- **ENDPOINT-2**：暗号化対象から外れた保存領域や不適切な回復鍵の権限によって、許可されていない人がデータを読めないか。画面ロック後に再認証なしで作業を再開できないか。
- **ENDPOINT-3**：更新の配布成功だけで適用済みとし、再起動待ち・サポート切れ・適用期限超過を見逃していないか。未承認アプリや拡張が是正対象から漏れていないか。
- **ENDPOINT-4**：一般利用者が未承認で昇格したり、期限後も昇格権限を使ったりして、管理方針を変更できないか。
- **ENDPOINT-5**：プロキシ設定の変更、直接接続、代替ネットワークやトンネルで、禁止した宛先へ接続できないか。許可していない外部接続元からデバッグサービスへ到達できないか。
- **ENDPOINT-6**：バックアップのコピーや復元経路を使って、復元権限のない人がデータを取得できないか。復元によって失効済み認証情報や古い許可設定を戻していないか。
- **ENDPOINT-7**：監視の停止・通信断・通知先の不達を、検知イベントがない正常状態として扱っていないか。
- **ENDPOINT-8**：紛失扱いの端末の既存セッションが、定めた制限期限後も使えないか。未到達の消去要求だけで対応を完了し、復旧確認前にアクセスを戻していないか。

## 実装判断の羅針盤

まず端末群と利用資産を特定し、端末・認証・監視・資産側の担当者を決めます。基準と観測の対象が一致することを確認してから、
状態悪化時の制限と復旧経路を選びます。方式の比較と受け渡しは[Managed developer endpoint](../../../../engineering/source-protection/managed-developer-endpoint/README.md)を参照してください。
例外は[Security exception lifecycle](../../governance-operations/psb-gov-002-security-exception-lifecycle/README.md)で対象・期限・承認を限定し、元の違反を良好へ書き換えません。

設定宣言、実効状態、アクセス制限の結果は別の情報です。観測失敗は証拠不足として扱い、確認した基準違反と区別します。

## 直接保証しない範囲

暗号化はログイン済みプロセスの読み出しを防がず、標準ユーザーでも自分が読めるソースを持ち出せます。
管理下の端末でも、許可したアプリや通信先の悪用、管理基盤の侵害、未知の攻撃は残ります。
認証情報の失効は[SOURCE-004](../psb-source-004-source-access-credential-lifecycle/README.md)、実行隔離は設計パターンの隣接領域へ引き継ぎます。
この記録は製品設定・端末診断・通知や隔離の実測を含みません。
