# PSB-CICD-005: Untrusted PR boundary

**外部PRで変えられるコードや成果物から、書き込み権限や秘密情報に届かないか。**

PRのテストへ公開用トークンを渡さなくても、そのテストが作ったスクリプトを後の公開ジョブが実行すれば、権限を使われます。PRのコードを動かす場所と、その結果を受け取る場所を一緒に確認します。

## 満たすべきこと

1. **変えられるものを追う。** PR作成者が変えられるコード、依存関係、設定、成果物、キャッシュ、出力と、それを後で使う処理を洗い出す。各処理が持つ権限も確認する。
2. **権限を渡さない。** 未確認のコードを実行する処理には、書き込み権限、秘密情報、クラウド認証用の権限、保護された環境を渡さない。永続ランナーや内部ネットワークなど、トークン以外の到達先も確認する。
3. **後続処理へ持ち込まない。** 権限を使う処理は、レビュー済みの変更から新しく始める。PRの実行で作ったスクリプトやキャッシュを信頼済みとして実行しない。データだけを渡す場合も、内容と使い道を検証する。

PRの実行を承認した人がいても、PRの内容や作られた成果物の出所は変わりません。ワークフロー、サービス側の設定、実際の実行を確認できない場合も、境界が守られているとは判断しません。

<a id="failure-checks"></a>

## 診断で確認する項目（異常時テスト）

- PRのコードや依存関係を変えると、トークンを渡していないつもりの処理から書き込み権限や秘密情報へ届かないか。
- PRが作ったスクリプト、成果物、キャッシュを、後続の権限付き処理が実行していないか。
- 実行の承認後にPRを更新したとき、古い承認だけで新しい内容を権限付き処理へ渡せないか。
- マージ後の処理がレビュー済みの変更から始まっているか。直接pushや保護設定の例外で未レビューの変更を混ぜられないか。
- fork設定や実際の実行を確認できないとき、設定例だけで合格と判断していないか。

これらは設計レビューや診断の確認項目です。試す場合は無害な入力と使い捨ての対象を使い、実際の秘密情報を取り出しません。

## このコントロールの範囲

対象は、低信頼の変更をCIで実行したり、その結果を後続処理で使ったりする経路です。個々の権限の絞り方は[CICD-004](../psb-cicd-004-workflow-authority-minimization/README.md)、キャッシュの信頼は[CICD-009](../psb-cicd-009-cache-trust-boundary/README.md)、ランナーの残存状態は[CICD-007](../psb-cicd-007-runner-lifecycle-isolation/README.md)で詳しく扱います。この分離だけで、レビュー済みコード自体の安全性は保証しません。

攻撃の流れは[教材](learning.md)、ジョブの分け方と受け渡すデータの検証は[engineering](../../../../engineering/cicd-security/untrusted-pr-boundary/README.md)、GitHub Actionsの設定例は[実装例](../../../../engineering/cicd-security/untrusted-pr-boundary/implementations/github-actions/README.md)を参照してください。6つの特性と根拠のIDは[control.yaml](control.yaml)、資料の採否は[Sources](../../../../sources/README.md#ref-cicd-010)、フレームワークとの関係は[マッピング](../../../../mappings/frameworks.yaml)、旧関係の採否は[移行台帳](../../../../docs/MIGRATION.md#2026-10-04cicd-005のframework関係を再照合)にあります。
