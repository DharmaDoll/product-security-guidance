# PSB-CICD-002: Workflow input handling

PRの題名を確認するだけのCIが、題名に含まれた文字列をコマンドとして実行してしまう。Workflowの設計者とレビュー担当者が、**外部から届く値を、処理の命令へ変えずに使えているか**を判断するcontrolです。

## 問いと直接の失敗

守るものは、CIの実行内容と検証結果、workspace、後続処理へ渡す状態です。外部の投稿者や侵害されたアカウントが変更できる題名、本文、branch名、入力値等が、スクリプトの構文や意図しない操作の指定として扱われることが直接の失敗です。

攻撃が成立するには、変更できる値が対象のイベント・jobへ届き、命令として解釈される箇所まで流れる必要があります。追加コマンドの実行後に利用できる認証情報、通信、保存状態が被害の大きさを決めます。入力に問題があるだけで、組織やcloud全体の権限を得るとは扱いません。

## 適用範囲と非適用

CIが外部入力をスクリプト、Action、呼出先プログラムへ渡す経路を扱います。Stepやjobの出力、生成ファイルを経由しても、入力の出所と最後の解釈箇所を追います。

表示名等に式があるだけで、コマンド注入とは判定しません。その値を実行内容へ取り込む経路があれば対象です。一般的なアプリケーションのinjection要件、未信頼コード自体を実行する許可、jobの権限、runnerの隔離、scannerの取得・運用はそれぞれ隣接領域へ渡します。

## 満たすべきこと

| 特性 | 確認すること |
|---|---|
| CI-INPUT-1 | 誰が値を変更でき、どのイベント・jobへ届けられ、どこで解釈されるかを特定する。値の名前だけで信頼済みとしない |
| CI-INPUT-2 | 未信頼値をスクリプトのソースへ埋め込まない。固定した命令とデータを分けて渡す |
| CI-INPUT-3 | 実際のshell・言語の規則に従って引数を保持し、値を再び命令として評価しない |
| CI-INPUT-4 | 値が操作・対象・オプションを選ぶ場合、許可する意味を限定する。一つの引数に保つことだけで、任意の操作を許可しない |
| CI-INPUT-5 | Action、呼出先スクリプト、出力、生成ファイルを通っても、次の解釈箇所までデータとしての扱いを確認する |
| CI-INPUT-6 | 実行箇所を対象に検査し、解析不能・対象不足・未確認を問題なしへ変えない。表示用の式を同じ欠陥として数えない |

実装方式は、構造化した引数、環境変数、入力をコード生成に使わないAPI等から選びます。文字を削除する方式や、すべての式を同じ規則で拒否する方式を唯一の合格条件にしません。根拠は[GitHub仕様](../../../../sources/README.md#spec-github-workflow-input)、[Bash仕様](../../../../sources/README.md#spec-bash-shell-expansion-5-2)、[引数の扱いに関するOWASP資料](../../../../sources/README.md#ref-command-input-defense)、[本PJの解釈](../../../../sources/README.md#ref-workflow-input-001)へ記録しています。

## 診断で確認する項目（異常時テスト）

診断や設計レビューに使う確認項目です。実行結果や脆弱性がないことの証拠ではありません。

| 試す条件 | できてはいけないこと・確認する扱い |
|---|---|
| 題名や本文に引用符、改行、コマンド区切りを含める | 固定した処理以外の命令が増える。値の取得から最後の解釈まで確認する |
| 変数へ渡した値に空白、ワイルドカード、空文字を含める | 引数の数や対象が意図せず変わる。対象shellでの渡し方を確認する |
| 環境変数に移した値を命令の評価処理へ渡す | データのまま渡したことを理由に、後段での再解釈を見逃す |
| 操作の指定へ未知の値、オプションに見える値、対象外のパスを渡す | 引数の引用だけで任意の操作・対象が許可される。未許可なら実行前に止まるか確認する |
| 同じ値をstep出力、Action入力、生成ファイル経由に変える | 経由しただけで信頼済みになり、命令として使用される |
| 表示用の式と、実行用の式を含む定義を比較する | 式の存在だけで両方を同じ欠陥とする。実行への流れを区別する |
| 検査対象の欠落、未対応構文、検査の失敗を起こす | 未検査の処理まで確認済みに含める。必須の確認ができなければ受入判断を止める |

## 実装判断と境界

[教材](learning.md)で題名から追加コマンドが生まれる理由を追い、[設計pattern](../../../../engineering/cicd-security/workflow-data-and-command-boundary/README.md)で入力の渡し方と操作の選び方を比較できます。今回はガイダンスと診断項目で完了とし、独自scannerや配布用workflowを必須にしません。

[CICD-004](../psb-cicd-004-workflow-authority-minimization/README.md)は侵害後に使える権限、[CICD-005](../psb-cicd-005-untrusted-pr-boundary/README.md)は未信頼コード・状態と権限付き処理の分離、[CICD-007](../psb-cicd-007-runner-lifecycle-isolation/README.md)はrunnerの残留状態を扱います。[DETECT-001](../../detection-verification/psb-detect-001-scanner-evidence-trust-boundary/README.md)へscannerと検査結果の信頼性を渡します。入力を修正しても、これらの境界が成立したことにはなりません。

旧4項目、scanner、中央配布、framework関係の扱いは[移行判断](../../../../docs/MIGRATION_CI_CD.md#workflow-input-migration)にあります。
