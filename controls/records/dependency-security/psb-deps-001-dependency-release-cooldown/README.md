# PSB-DEPS-001: Dependency release cooldown

**新しく公開された依存パッケージを、決めた期間が過ぎる前に実行・採用していないか。**

更新ボットが公開直後のバージョンを選び、CIでインストールするとします。後から不正なリリースと分かってマージを止めても、インストール時のコードは既に動いています。待機期間は、その版について警告が出る時間を確保するためのものです。

## 満たすべきこと

1. **対象を特定する。** 新たに選ぶパッケージの名前、正確なバージョン、取得元を確認する。承認した情報源の公開時刻と信頼できる現在時刻で経過時間を判定する。
2. **実行前に止める。** 決めた待機期間を満たさない版は、依存パッケージのコードを実行する前、かつ変更をマージする前に止める。開発者、ボット、別の依存解決経路にも同じ判断を適用する。
3. **分からなければ通さない。** 公開時刻が取れない、古い情報しかない、判定処理が失敗した場合は合格にしない。緊急採用は対象の版、理由、担当者、別の承認者、期限を明示し、通常の待機条件を満たした扱いにしない。

<a id="failure-checks"></a>

## 診断で確認する項目（異常時テスト）

- 公開直後の版を選んだとき、検査より先にインストール時のコードやビルド用プラグインが動いていないか。
- 更新ボットや別のパッケージ管理手段、設定の上書きから、待機条件を迂回できないか。
- 公開時刻の取得失敗や不明な取得元を、十分に古い版として通していないか。
- 緊急例外を別のパッケージ、別バージョン、期限後の更新にも使えてしまわないか。

ここに書いたのは確認項目であり、実際の導入や診断の結果ではありません。

## このコントロールの範囲

対象は、新しい依存版を選ぶ追加・更新・ロックファイルの再生成です。既にレビューしたロックファイルをそのまま使うときの完全性は別の判断です。待機期間を過ぎても、パッケージが安全とは言えません。脆弱性、来歴、取得物の同一性、インストール時の実行制御は別に確認します。
