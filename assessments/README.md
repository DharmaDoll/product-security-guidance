# 評価

評価は、コントロール記録や実装例の存在ではなく、特定の組織、システム、リポジトリ、環境で、
セキュリティ特性が成立しているかを判断する成果物です。

## パイロットでの判断

このパイロットでは、評価用スキーマや証拠を模したテスト用データを作りません。
まずコントロールと設計・実装の情報設計を評価します。

将来追加する評価は次を満たす必要があります。

- 対象範囲と評価時点を固定する。
- セキュリティ特性ごとに、観測元とその情報を信頼する根拠を示す。
- `PASS`、`FAIL`、`NOT_CHECKED`、`INCOMPLETE`、`ERROR`を必要に応じて区別する。
- サンプル、文書、合成したテスト用データから、組織へ導入済みであると推論しない。
- 実在する秘密情報、認証情報、非公開のソースコード、本番データをリポジトリへ保存しない。
- 横断分析の`直接`や`隣接`を、組織への導入結果へ変換しない。
- 複数の攻撃段階を評価する場合、前段の判断、引き渡す識別子、後段での強制状態を別々に観測する。

旧来の個別確認項目と証拠欄を移すかどうかは、コントロール記録のパイロット評価後に決めます。
